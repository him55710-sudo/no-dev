# 업무 기능과 코드 연결

`업무 기능 만들기`에서 이름·사용자 설명을 작성하고 여러 폴더의 파일·함수·규칙을 선택한다. 예를 들어 공유 권한 검사, 수정 API, 편집 화면을 `프로젝트 공유`로 묶을 수 있다. 이 동작은 `.pureobom/specs.json`의 기능 메타데이터만 저장한다. 소스를 이동하지 않으며 에이전트를 실행하지 않는다.

기능이 생기면 시스템 첫 화면에 사용자 정의 기능과 `코드 구조`가 나타난다. 기능을 두 번 누르면 선택한 코드 대상과 실제 컴파일러 호출·렌더링 관계로 내려간다. 연결선은 원래 컴파일러 관계 ID를 보존하여 개별 소스 근거를 열 수 있다. `코드 구조`는 미분류·미지원 코드를 포함한 전체 소스 탐색 경로다. 업무 의존성으로 오인하지 않도록 이 탐색 항목 자체에는 기능 연결선을 그리지 않는다.

하나의 코드는 여러 업무 기능에 포함될 수 있다. 코드를 선택하면 포함된 기능으로 돌아가는 버튼을 제공한다. 트리와 캔버스는 같은 원본 노드 ID를 사용하며, 기능 안에서 하위 규칙으로 내려갈 때 탐색 경로를 유지한다. 기능 내부의 코드 호출이 다른 기능에도 포함되어 있으면 그 실제 참조가 각 기능의 연결에 나타날 수 있다. 이 연결은 정적 참조이며 기능 간 업무 계약이나 런타임 실행을 증명하지 않는다.

기능을 선택한 상태에서 Living Spec을 저장하고 구현할 수 있다. 작업 범위는 묶음의 원본 코드와 정적으로 연결된 호출·화면을 따라 확장한다. 이름과 설명은 사용자 작성 정보로 표시하며 코드로 입증한 동작과 구별한다. 기능의 범위를 바꾸면 기존 설계의 목표를 유지하고 구현 기준의 재검토를 요구한다. 구현 검토를 받은 뒤 범위를 바꿔도 이전 검토를 바로 반영하지 않는다. 실제 반영 전에 현재 설계와 기능 연결을 다시 검사한다.

Hook 인수나 JSX 속성으로 넘긴 함수는 [함수 전달 관계](CALLBACK_RELATIONS.md)로 함께 추적한다. 직접 호출·실제 런타임 실행과 구분하여 표시하며, 연결선의 근거에서 전달한 원문으로 이동할 수 있다.

`기능 이름·코드 묶음 편집`으로 이름·설명·포함 대상을 바꿀 수 있다. 같은 종류·내용을 가진 이동 대상이 유일하면 코드 연결을 다시 찾는다. 이름과 본문이 함께 바뀌거나 후보가 여러 개이면 임의로 고르지 않고 재연결 필요로 표시한다. 편집 화면에서 찾지 못한 참조는 기본적으로 유지되며, 사용자가 제외하거나 새 대상을 선택할 수 있다. 미연결 코드가 있는 기능의 구현·기준 확정은 거절한다.

묶음을 해제해도 코드와 저장된 설계는 보존한다. 연결되었던 설계는 재연결 상태로 표시하고 새 대상을 명시적으로 선택하게 한다. 다른 설계의 저장이나 기준 재확정도 기능 메타데이터를 보존한다. 신뢰한 작업 공간에서만 메타데이터를 쓰고, 리비전·그래프 버전·파일 외부 변경이 발견되면 저장을 거절한다.

파일 알림이나 새로고침 요청이 분석 도중 겹치면 이전 분석 결과를 버리고 최신 요청까지 기다린다. 기능 생성·해제 요청도 이 완료를 기다리므로 삭제한 기능이 이전 그래프에 남은 상태로 완료를 알리지 않는다. 계속되는 편집 때문에 안정된 결과를 얻지 못하면 분석 중단을 명시하고 재분석을 요청한다. [겹치는 분석을 포함한 호스트 검사](evidence/system-workspace/2026-10-16/refresh-integration.json)는 기능 해제 도중 두 번째 새로고침을 발생시켜 이 순서를 확인한다.

현재 한도는 프로젝트당 기능 100개, 기능당 직접 연결 100개이며 설계와 기능 메타데이터 파일 전체는 1MB다. 기능 안에 또 다른 사용자 기능을 넣는 중첩 분류는 아직 지원하지 않는다. 폴더와 코드의 실제 하위 구조는 계속 탐색할 수 있다. 자동 업무 의미 추론, 분류 추천, 수동 정의 없이 완성된 시스템 경계를 복원하는 기능을 제공한다고 주장하지 않는다.

## 검증 범위

- `tests/workspace-features.test.ts`: 다대다 연결, 원래 컴파일러 관계 보존, 호출 범위, 묶음 변경 시 기준 드리프트, 이동·중복·미연결 처리, 메타데이터 충돌 및 해제 후 설계 보존.
- `pnpm extension:design-test`: 실제 VS Code에서 여러 폴더의 코드 묶음 저장·설계 저장·해제, 에이전트 미실행 및 원본 보존, 열린 파일의 외부 원자적 교체 뒤 디스크 해시 분석. [호스트 검사 결과](evidence/system-workspace/2026-10-16/features-integration.json).
- `pnpm extension:recovery-test`: 실제 설치본에서 업무 기능을 만든 뒤 구현·검토·반영·기준 확정·재시작·undo·다음 구현·프로세스 강제 종료와 파일 복구. 범위 변경 후 예전 구현 검토의 반영 거절도 확인했다. [설치본 검사 결과](evidence/system-workspace/2026-10-16/features-installed.json). stdio 테스트 응답기를 사용하는 호스트 통합 검사이며 외부 모델 품질 검증은 아니다.
- [화면 조작 증거](evidence/system-workspace/2026-10-16/business-features.jpg): 합성 소스에서 실제 React 화면의 기능 생성·내부 탐색·연결선 근거·코드에서 기능 복귀를 조작했다. VS Code Webview의 마우스·키보드 전체 조작과 구별한다.

전체 기획의 남은 사항은 [진행 기준](SYSTEM_WORKSPACE_STATUS.md)을 따른다.
