## 구현할 사용자 흐름

1. 프로젝트를 열면 지원 언어, 분석 가능한 범위, 필요한 로컬 도구를 확인한다.
2. 모델 없이 문법 기반 설명을 읽거나, 설치된 Ollama 모델을 선택한다. 최초 설치와 모델 다운로드에는 인터넷·디스크 공간이 필요하지만 로컬 추론에는 유료 API 키가 필요하지 않다. PC의 메모리·연산·전력 비용은 남는다.
3. 로컬 AI를 실행하기 전에 전달할 현재 파일, 크기, 작업 목적을 확인한다. 프로젝트 전체·비밀 설정·대화 기록을 자동 첨부하지 않는다.
4. 한국어 또는 영어로 목적·흐름·변경 지점을 읽고 코드 근거로 이동한다. 문법 분석 결과와 모델 추론을 구별한다. 모델이 인용한 원문은 실제 파일과 대조한다.
5. 자연어 수정 또는 최적화를 요청한다. 모델은 변경안을 제안하고, 프로그램이 실제 원문과 범위를 검증한다. 자동 실행·자동 적용·자동 저장은 하지 않는다.
6. 변경 전후 차이, 검증 결과와 남은 불확실성을 보고 적용하거나 버린다. 파일이 바뀌면 이전 제안은 무효이며 정상적인 편집기 undo가 가능해야 한다.
7. 최적화는 결과 동일성 검사와 측정을 함께 남긴다. 측정하지 않은 제안에 속도 향상 수치나 '최적화 완료'를 붙이지 않는다.

## 연결 설계

- 첫 연결은 데스크톱 VS Code 확장 호스트에서 `127.0.0.1`의 Ollama HTTP API로만 한다. 외부 주소·리디렉션·클라우드 모델·유료 API로의 자동 대체를 허용하지 않는다. 원격 VS Code와 공개 웹 데모에서 로컬 PC에 연결하는 기능은 별도 검증 전까지 지원으로 표기하지 않는다.
- 모델의 JSON 출력도 검증해야 하는 입력이다. 인용은 실제 문자열, 변경은 유일한 원문 범위에 연결한다. 모델은 파일 경로, 셸 명령, 네트워크 주소, 적용 여부를 실행 권한으로 사용할 수 없다.
- 모델 선택과 요청은 사용자의 명시적 조작으로 시작한다. 큰 요청을 몰래 자르지 않는다. 코드 내용은 로그·공개 피드백에 자동 저장하지 않는다.
- 로컬 문법 분석·편집 경로는 모델 없이도 유지한다. 무거운 분석과 추론은 UI와 분리한다. 요청 중 파일 변경·탭 전환·취소를 처리한다.

## 실제 프로젝트 검증 방법

본 저장소만 분석한 결과를 외부 프로젝트 검증으로 부르지 않는다. 공개 라이선스를 확인한 외부 저장소를 별도 검증 폴더에 고정 커밋으로 가져온다. URL·커밋·대상 파일·작업 목적·수정 diff·검증 명령·도구 버전·결과를 공개한다. 원격 저장소에 변경을 보내지 않는다. 비공개 사용자 파일·계정·토큰은 공개 자료에 포함하지 않는다.

외부 프로젝트의 기존 테스트와 변경 후 테스트를 구분하고, 모델 추론은 모델 이름·digest·환경·시간을 남긴다. 가짜 HTTP 서버 검사와 실제 Ollama 검사를 별도 집계한다. 모델 실패·틀린 설명·수정 거절도 기록한다. 테스트 성공은 사용성·전체 언어 정확성·수요를 증명하지 않는다.

## 공개 기록 규칙

각 작업 기록에는 목적, 실제 변경 파일, 사용한 외부 자료, 실행한 검증과 결과, 발견한 실패, 남은 범위, 커밋 또는 후속 연결을 남긴다. 이전 세션의 비공개 내부 추론이나 도구 로그 전체를 지어내지 않는다. 과거 작업은 Git 이력과 남은 검증 파일로 확인 가능한 것만 소급 정리한다. 비밀·개인정보를 제외한 재현 가능한 작업 사실을 공개한다.
