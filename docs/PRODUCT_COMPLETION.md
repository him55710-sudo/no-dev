# 제품 완성 계획 · Product completion plan

상태 기준: **2026-10-16 · 진행 중**. 시작 커밋은 `7603971`이다. 이 문서는 공개 개발 계약이며 완료 보고서가 아니다. 세부 변경·실패·검증 이력은 [에이전트 작업 기록](AGENT_WORKLOG.md), 언어별 범위는 [지원 및 검증 표](LANGUAGE_SUPPORT.md), 원자료는 [검증 자료](evidence/local-ai/README.md)에서 확인한다.

## 현재 상태

- **0.7 개발 소스:** 로컬 Ollama 연결, 정확한 원문에 연결한 다중 범위 편집, native diff·적용·undo, 기존 프로젝트 명령 실행, 전후 시간·메모리 측정이 있다. 공개 안정판과 Pages 데모는 **0.6.0**이며 새 기능 배포와 구분한다.
- **모델 없는 원문 읽기·수정:** JS/TS의 일부 구문·JSX, [JSON/JSONC](JSON_DATA.md), 설치 도구를 사용하는 [Python](PYTHON_SOURCE.md)·[Go](GO_SOURCE.md), 포함된 파서의 [HTML/CSS](HTML_CSS_SOURCE.md). 전체 구문·타입·프로젝트 의미 분석을 제공하는 것은 아니다.
- **실제 외부 검사:** Python itsdangerous, JavaScript clsx, Go Google UUID에서 고정 오류 발견과 undo 복구를 확인했다. [HTML/CSS modern-normalize](evidence/local-ai/web-source-project.md)는 Chrome 전체 54개 중 실패 **7→9→7**을 확인했다. 원래 실패와 assertion 없는 TODO 8개를 보존한다. 모든 외부 프로젝트가 전체 통과했다는 뜻은 아니다.
- **남은 우선순위:** Rust·Java·C#·SQL의 전용 도구와 실제 프로젝트, 모델의 분기·경계·데이터 의미 오류, 환경별 사용 흐름, 실제 성능 개선의 근거다. 이미 측정한 Python 모델 제안은 느려져 채택하지 않았다. 원격 VS Code·모든 브라우저·모든 언어 정확성은 보장하지 않는다.

외부 검증 도구·기록 소스 `493cd04`의 [Windows·Ubuntu CI](https://github.com/him55710-sudo/pureobom/actions/runs/38891611946)는 각각 핵심 **200개**, 개발/설치 각 **38개**, production 모드·런타임 7개 해시와 추출 도구 실행에 성공했다. [CI 원자료](evidence/local-ai/web-project-ci.json). 외부 Chrome 프로젝트는 별도로 Windows에서 실행한 기록이며 CI의 성공 수에 합치지 않는다. 이전 증분의 커밋별 CI와 설치본·실제 모델·화면 기록은 작업 기록에서 추적한다.

## 요청과 우선순위

비개발자가 AI로 만든 코드를 자신의 말로 이해하고, 설명에서 수정하고, 결과를 검증하며 최적화한다. 주 제품은 VS Code 확장이다. API 사용료 없이 사용할 수 있어야 하며, 여러 프로그래밍 언어와 실제 프로젝트에서 작동해야 한다. 사용자는 Ollama 로컬 모델 활용을 허용했다. 공개 기획과 에이전트의 변경·실패·검증 기록을 먼저 갖춘다. 모집·홍보·Marketplace 계정은 이 개발의 선행 조건이 아니다.

## 구현할 사용자 흐름

1. 프로젝트를 열면 지원 언어, 분석 가능한 범위, 필요한 로컬 도구를 확인한다.
2. 모델 없이 문법 기반 설명을 읽거나, 설치된 Ollama 모델을 선택한다. 최초 설치와 모델 다운로드에는 인터넷·디스크 공간이 필요하지만 로컬 추론에는 유료 API 키가 필요하지 않다. PC의 메모리·연산·전력 비용은 남는다.
3. 로컬 AI를 실행하기 전에 전달할 현재 파일, 크기, 작업 목적을 확인한다. 프로젝트 전체·비밀 설정·대화 기록을 자동 첨부하지 않는다.
4. 한국어 또는 영어로 목적·흐름·변경 지점을 읽고 코드 근거로 이동한다. 문법 분석 결과와 모델 추론을 구별한다. 모델이 인용한 원문은 실제 파일과 대조한다.
5. 자연어 수정 또는 최적화를 요청한다. 모델은 변경안을 제안하고, 프로그램이 실제 원문과 범위를 검증한다. 자동 실행·자동 적용·자동 저장은 하지 않는다.
6. 변경 전후 차이, 검증 결과와 남은 불확실성을 보고 적용하거나 버린다. 파일이 바뀌면 이전 제안은 무효이며 정상적인 편집기 undo가 가능해야 한다.
7. 최적화는 결과 동일성 검사와 측정을 함께 남긴다. 측정하지 않은 제안에 속도 향상 수치나 '최적화 완료'를 붙이지 않는다.

## 연결 설계

- 첫 연결은 데스크톱 VS Code 확장 호스트에서 `127.0.0.1`의 Ollama HTTP API로만 한다. 외부 주소·리디렉션·클라우드 모델·유료 API로의 자동 대체를 허용하지 않는다. 원격 VS Code와 공개 웹 데모에서 로컬 PC에 연결하는 기능은 별도 검증 전까지 지원으로 표기하지 않는다.
- 모델의 JSON 출력도 검증해야 하는 입력이다. 인용은 실제 문자열, 변경은 유일한 원문 범위에 연결한다. 모델은 파일 경로, 셸 명령, 네트워크 주소, 적용 여부를 실행 권한으로 사용할 수 없다.
- 모델 선택과 요청은 사용자의 명시적 조작으로 시작한다. 큰 요청을 몰래 자르지 않는다. 코드 내용은 로그·공개 피드백에 자동 저장하지 않는다.
- 로컬 문법 분석·편집 경로는 모델 없이도 유지한다. 무거운 분석과 추론은 UI와 분리한다. 요청 중 파일 변경·탭 전환·취소를 처리한다.

## 실제 프로젝트 검증 방법

본 저장소만 분석한 결과를 외부 프로젝트 검증으로 부르지 않는다. 공개 라이선스를 확인한 외부 저장소를 별도 검증 폴더에 고정 커밋으로 가져온다. URL·커밋·대상 파일·작업 목적·수정 diff·검증 명령·도구 버전·결과를 공개한다. 원격 저장소에 변경을 보내지 않는다. 비공개 사용자 파일·계정·토큰은 공개 자료에 포함하지 않는다.

외부 프로젝트의 기존 테스트와 변경 후 테스트를 구분하고, 모델 추론은 모델 이름·digest·환경·시간을 남긴다. 가짜 HTTP 서버 검사와 실제 Ollama 검사를 별도 집계한다. 모델 실패·틀린 설명·수정 거절도 기록한다. 테스트 성공은 사용성·전체 언어 정확성·수요를 증명하지 않는다.

## 공개 기록 규칙

각 작업 기록에는 목적, 실제 변경 파일, 사용한 외부 자료, 실행한 검증과 결과, 발견한 실패, 남은 범위, 커밋 또는 후속 연결을 남긴다. 이전 세션의 비공개 내부 추론이나 도구 로그 전체를 지어내지 않는다. 과거 작업은 Git 이력과 남은 검증 파일로 확인 가능한 것만 소급 정리한다. 비밀·개인정보를 제외한 재현 가능한 작업 사실을 공개한다.

## 완료 판단

P0–P6의 근거가 모두 있어야 이 계획을 완료로 바꾼다. 미설치 도구나 외부 게시 권한 부족을 다른 구현 작업을 중단하는 이유로 사용하지 않는다. 제약은 구체적으로 기록하고 가능한 독립 작업을 계속한다. 모든 언어·모든 프로젝트에서 완벽하다는 보장은 하지 않는다.
