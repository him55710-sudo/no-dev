# 작성 중 설계 보관

설계 패널에서 입력한 내용은 확정된 설계와 별도의 로컬 초안으로 보관한다. 이름이나 목록의 빈 줄처럼 작성 중인 값도 유지한다. 왼쪽 `작성 중 초안`에서 다시 열 수 있으며, `초안을 이 기기에 보관했습니다` 표시가 나온 입력은 패널을 닫거나 VS Code를 재시작한 뒤 복원한다.

자동 보관은 `.pureobom/specs.json`, 원본 코드, 구현 작업을 변경하지 않는다. `설계만 저장` 또는 `저장하고 구현`을 눌러야 확정한다. 확정에 성공한 초안만 제거한다. `초안 버리기`도 확정된 설계를 변경하지 않는다.

## 다른 변경과 이어 쓰기

초안에는 작성 당시의 설계 전체와 코드 기준을 함께 보관한다. 최신 설계가 달라지면 입력을 유지하고 확정을 막는다. `최신 설계와 초안 비교`에서 작성 시작 시·최신 설계·내 초안을 비교하고, 확인란을 선택한 뒤 `이 기준으로 초안 이어 쓰기`를 누른다. 이때 편집 기준만 바꾸며, 입력한 목표와 확정된 설계는 그대로 둔다. 이후 별도로 설계를 저장한다.

비교를 연 뒤 설계나 분석 결과가 다시 바뀌면 이전 비교로 이어 쓰기를 거절한다. 저장된 설계의 리비전이 같아도 수동으로 내용이 바뀌면 차이를 감지한다. 원래 설계나 코드 대상을 찾지 못하면 입력은 계속 복사·편집할 수 있으나 대상을 복구하기 전에는 확정할 수 없다.

동일 프로젝트의 다른 창에서 초안을 수정했으면 오래된 리비전으로 덮어쓰지 않는다. 실패한 입력은 현재 화면에 남기고 오류를 표시한다. 이 경우 입력을 따로 복사한 뒤 패널을 다시 열어 저장된 초안을 확인한다. 서로 다른 창의 초안을 자동 병합하는 기능은 없다.

## 저장 위치와 한계

- 확장의 VS Code 전역 저장 공간 아래 `design-drafts/<프로젝트 경로 해시>/<설계 ID 해시>.json`에 보관한다. 현재 기기·VS Code 프로필 기준이며 Git이나 계정 간 동기화 대상이 아니다. 프로젝트 경로를 바꾸면 다른 보관 위치로 취급한다.
- 프로젝트마다 최대 100개, 기록 하나당 1MB까지 허용한다. 손상된 기록이나 한도 초과를 발견하면 오류를 표시하고 기존 파일을 보존한다.
- 요청은 초안별로 순서대로 처리한다. 파일은 임시 파일을 동기화한 뒤 교체하며, 동시에 쓰는 제품 프로세스는 프로젝트 잠금과 리비전 검사로 조정한다.
- 아직 `보관하고 있어요`인 입력은 브라우저 요청 대기열에만 남아 있을 수 있다. 이때 패널이나 프로세스를 강제 종료하면 마지막 입력까지 복원된다고 보장하지 않는다. 전원 손실·파일 시스템 자체 장애의 복구 보장도 이번 검증에 포함하지 않는다.
- 브라우저 데모에서 저장 연결이 없으면 `이 화면에서 작성 중`으로 표시하며 영구 보관으로 안내하지 않는다.

## 검증

`tests/design-drafts.test.ts`는 불완전한 입력 복원, 프로젝트 분리, 오래된 쓰기 거절, 명시적 기준 변경, 실패 시 보존, 같은 리비전의 수동 변경과 손상 기록을 검사한다. 전체 [회귀 검사 요약](evidence/system-workspace/2026-10-16/drafts-validation.json)에서 194개 통과를 확인했다.

[VS Code 호스트 검사](evidence/system-workspace/2026-10-16/drafts-integration.json)는 같은 화면 요청 처리기를 통해 초안 보관·재열기·확정 후 제거·충돌 후 비교·기준 변경을 확인한다. [설치본 검사](evidence/system-workspace/2026-10-16/drafts-installed.json)는 실제 VSIX의 해시와 Production 실행 모드를 확인하고 별도의 VS Code 실행 간에 빈 이름과 빈 목록까지 복원했다. 기준 설계가 바뀐 뒤에도 원래 초안의 문맥이 유지되고, 명시적 버리기가 확정된 설계를 변경하지 않는 것도 검사했다.

[비교 화면](evidence/system-workspace/2026-10-16/draft-comparison.jpg)은 실제 React 화면에 합성 자료와 브라우저 저장 모의 연결을 제공해 직접 조작한 결과다. 새로고침 후 복원, 외부 설계 변경 후 확정 차단, 비교를 연 뒤 추가 변경 시 거절, 다시 비교한 뒤 명시적 확정까지 확인했다. 설치본 마우스·키보드 전체 흐름이나 실제 외부 모델 실행 증거로 취급하지 않는다.
