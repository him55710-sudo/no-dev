# 한국어 프로젝트 읽기와 수정

명령: **풀어봄: 시스템 설계 워크스페이스 열기**로 읽기 화면을 연다. **구조와 고급 도구**에서 기존 구조 탐색과 설계를 사용할 수 있으며 전환 중 작성하던 설계와 탐색 위치는 유지된다. 현재 우선순위는 [각 파일의 코드를 쉽게 해석하고 수정하는 경험](CODE_READING_PRODUCT.md)이다.

## 사용자 흐름

1. 프로젝트 폴더를 열고 **내 코드를 쉬운 말로 읽기**를 누른다.
2. 쉬운 제목으로 읽고 싶은 파일을 찾는다. 실제 코드를 나누어 목적·입출력·조건·예외·처리 순서·작성 이유·수정 방법을 읽는다. **코드와 나란히 보기**로 해당 원문을 함께 볼 수 있다.
3. 설명에서 **이 요청으로 수정 준비하기** 또는 **이 부분을 내가 원하는 대로 바꾸기**를 누르고 원하는 결과를 적어 **변경안 만들기**를 누른다. 제시된 요청은 자유롭게 고칠 수 있다.
4. 별도 작업 복사본에서 생성한 변경과 실제 검사 결과를 확인한다. 한국어 비교는 변경 전후의 실제 코드에서 만든다.
5. 확인한 변경을 **내 프로젝트에 반영하기**로 적용한다. 원본이 달라졌거나 검사가 실패했으면 반영을 막는다. 반영 이후 **이번 변경 되돌리기**로 복원할 수 있다.

## 실제 연결

설치된 Codex의 공식 stdio App Server를 사용하며 로그인은 Codex가 관리한다. 이 확장이 로그인 비밀이나 API 키를 읽어 복사하지 않는다. 이 컴퓨터에서는 ChatGPT 로그인 상태를 확인했다. 모델 설정이 비어 있으면 해당 Codex의 기본 모델을 사용한다. 코드와 설계 내용은 연결된 AI 제공자에게 전달되며 계정 사용량이 발생한다.

요약은 `read-only` 세션과 구조화된 응답을 사용한다. 구현은 Git 작업 복사본의 `workspace-write` 세션을 사용한다. 실제 공급자 호출과 고정 응답 테스트는 별개다. 공식 프로토콜: <https://learn.chatgpt.com/docs/app-server>.

## 해석과 검증의 경계

AI가 읽는 대상은 수집한 코드·문서의 전체 본문이다. 큰 파일도 나누어 읽으며 조용히 잘라 보내지 않는다. 각 파일 설명에 실재하는 원문 인용을 요구하고, 전체 설명의 각 부분에 모든 파일이 연결되는지 검사한다. 인용 일치는 의미 해석의 정확성이나 런타임 동작을 증명하지 않는다. 이 구분을 화면에서도 표시한다.

파일 상세 읽기는 각 원문 줄을 정확히 한 번 설명에 연결한다. 64,000자 이하의 파일은 전체 파일 문맥도 함께 제공하고, 더 큰 파일은 파일의 시작과 각 부분의 앞뒤 문맥을 제공하며 제한을 표시한다. 같은 파일 안의 멀리 떨어진 관계나 다른 파일의 동작을 항상 해석할 수 있다는 뜻은 아니다. 작성 이유는 명시된 근거·추정·미확인으로 구분한다.

요약과 변경 비교는 모델이 수행한다. 검사 결과는 별도 프로세스에서 실제 실행한 명령의 종료 상태로 기록한다. 모델이 말한 “통과”를 검사 결과로 사용하지 않는다. 한국어 비교 역시 모든 변경 경로와 각 버전의 원문 인용을 검사한다.

내용·모델 설정·프롬프트 버전별로 설명을 캐시한다. 전체 요약도 같은 입력이면 재사용한다. 코드가 바뀌면 이전 설명임을 표시하고 수정 요청을 막는다. 부분별 입력 초안을 별도로 보존한다. 진행 메시지는 변경된 상태만 보내며 큰 구조 그래프를 매번 다시 보내지 않는다.

## 현재 범위

- 로컬 VS Code의 신뢰한 작업 공간에서 AI 연결과 수정이 가능하다.
- 최대 500개 파일, 전체 8MB, 파일당 512KB를 구조 분석한다. 제외·크기 제한은 알림으로 표시한다.
- JS/TS, JSON/JSONC, Markdown, Python, Go, Rust, Java, C#, HTML/CSS, SQL 본문을 읽는다. 함수·호출 관계를 정밀하게 추출하는 지도는 JS/TS 중심이며, 다른 언어의 설명은 AI의 해석이다.
- 의존성·빌드 결과·Git 내부·테스트 실행 결과·숨김 파일(일부 .github 문서 제외)과 이름으로 식별되는 비밀 설정은 설명 대상에서 제외한다.
- 현재 여러 파일의 코드 반영은 커밋이 있는 Git 저장소 최상위 폴더와 package.json의 test/typecheck/check/build 검사 명령이 있는 프로젝트를 대상으로 한다. 없는 프로젝트도 읽고 탐색할 수 있지만 반영은 지원하지 않는다. 모든 프레임워크를 자동으로 설정해 주는 완성형 개발 환경은 아니다.
- 설치된 실행 환경과 의존성이 프로젝트의 검사 도구와 호환되어야 한다. 새 의존성 설치 또는 제한 밖의 실행은 별도 요청으로 나타날 수 있다.
- 기존 시스템 작업 엔진은 커밋 `694bc81`의 파일을 복사해 통합했다. 다른 작업 트리의 진행 중인 변경은 수정하지 않았다.

## 검증 재현

`PUREOBOM_RUN_CODEX=1 pnpm reader:live-test`: 실제 AI의 파일별 상세 해석. 실행마다 새 캐시를 사용하며 원문 보존을 검사한다. PowerShell에서는 `$env:PUREOBOM_RUN_CODEX='1'`을 설정한 뒤 명령을 실행한다.

`PUREOBOM_RUN_CODEX=1 pnpm extension:code-reading-live-test`: 설치본에서 공개 배송비 예제를 실제로 읽고, 설명 범위에 연결한 요청으로 여러 파일 수정·검사·전후 설명·반영·독립 동작 확인·되돌리기를 수행한다. 실제 AI 사용량이 발생한다. [실행별 결과와 실패 기록](evidence/code-reading/README.md).

`pnpm reader:preview`: 앞선 실제 파일 해석 결과를 화면에 보여주는 개발용 검사 페이지다. 프로젝트 개요와 전송은 고정 예시이며 이 페이지가 실제 수정이나 검사를 수행하지 않는다.

`scripts/check-agent-connection.mjs`: 실제 실행기·로그인 연결 확인, 추론 없음.

`scripts/check-live-project-reader.mjs`: 실제 AI의 본문 해석과 원문 근거 검증.

`scripts/test-project-reader.mjs`: 설치한 VSIX의 공개 프로젝트 복사본을 실제 AI로 읽고 수정한다. 실제 AI 사용량이 발생한다. 테스트 환경은 별도 VS Code 프로필이며 사용자 기본 프로필의 신뢰 설정을 바꾸지 않는다. 모델 응답을 고정한 대체 제공자를 사용하지 않는다. 프로젝트의 기존 잠금 파일로 로컬 의존성 저장소를 복원하는 작업만 테스트가 준비한다.

검증 대상은 `sindresorhus/escape-string-regexp` 복사본이다. 오래된 검사 도구를 위해 Node 22.21.1을 사용하고, 상위 개발 저장소의 TypeScript 설정이 섞이지 않도록 별도 임시 폴더에서 실행한다. 원래 `xo && ava && tsd` 검사를 유지한다. 변경 요청은 비문자열 입력의 안내를 한국어로 바꾸고 입력 확인을 별도 함수로 분리하며 관련 회귀 검사를 추가하는 것이다. 원본 공개 저장소에는 푸시하지 않는다.
