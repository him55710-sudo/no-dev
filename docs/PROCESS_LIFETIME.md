# 구현 작업의 프로세스 종료와 프로젝트 잠금

2026-10-16. 구현 결과의 반영·되돌리기·복구와 검사 취소에 대한 수정 기록이다. 전체 제품 완성을 뜻하지 않는다.

## 확인한 문제

- [기존 Windows CI](https://github.com/him55710-sudo/no-dev/actions/runs/38880067084/job/116904379300)는 원본 변경 거절 검사에서 프로젝트 잠금을 얻지 못했다. 이전 코드는 프로젝트 경로의 해시를 28,000개 TCP 포트 중 하나에 대응시켰다. 해당 실행은 운영체제 오류 코드를 남기지 않았으므로 다른 서비스와의 충돌·예약 포트 중 어떤 원인이었는지는 확정하지 않는다. 같은 실행의 Linux 작업은 설치본 복구까지 통과했다.
- 로컬 전체 검사에서는 `taskkill /T /F`가 성공하고 검사 프로세스의 exit가 확인됐는데도 출력 스트림 close를 기다리다가 20초 종료 확인 한도에 걸렸다. 완료 처리가 프로세스 종료와 스트림 종료를 구별해야 했다.

## 변경과 검증

Windows는 명명된 파이프, Linux는 추상 도메인 소켓으로 프로젝트 잠금을 잡는다. 전체 경로 해시를 사용하며 같은 프로젝트의 두 번째 쓰기는 거절한다. 정상 해제와 프로세스 강제 종료 모두 운영체제가 자원을 반환한다. 이전 TCP 포트를 다른 프로그램이 점유해도 새 잠금은 동작한다. Windows의 경로 대소문자 차이는 같은 잠금으로 처리한다. 다른 프로젝트의 잠금은 동시에 얻을 수 있다.

Windows 검사 중단은 프로세스 트리 종료 명령의 성공과 직접 실행한 프로세스의 종료를 모두 확인한 뒤 출력 스트림을 정리한다. 정상 완료는 여전히 출력을 다 읽은 후 결과를 반환한다. 종료를 확인하지 못하면 오류로 남기며, 시간 초과나 사용자 취소를 검사 통과로 바꾸지 않는다.

`tests/agent-recovery.test.ts`는 실제 별도 Node 프로세스를 강제 종료하고 재획득을 확인한다. `tests/agent-verification.test.ts`는 실제 패키지 관리자로 실행한 부모·자손 프로세스의 PID를 기록하고 시간 초과·취소 후 두 프로세스가 존재하지 않는지 검사한다. 고정 시간 대기만으로 종료를 추정하지 않는다.

로컬 전체 검사 결과는 [process-lifetime-tests.json](evidence/system-workspace/2026-10-16/process-lifetime-tests.json), 설치본 다섯 차례 실행·부분 반영 강제 종료·복구 결과는 [process-lifetime-installed.json](evidence/system-workspace/2026-10-16/process-lifetime-installed.json)에 있다. 설치본 검사는 결정적인 테스트용 응답기를 사용하므로 실제 모델 품질이나 화면 전체 조작을 증명하지 않는다.

## 제한

외부 편집기를 잠그지는 않는다. 반영 시 원본·제안 해시 검사를 유지한다. 구버전과 신버전은 잠금 방식이 다르므로 같은 프로젝트에서 동시에 사용하지 않는다. macOS 등 다른 운영체제는 이전 루프백 방식을 사용하며 이번 검증 범위에 포함하지 않는다. 실행 중인 에이전트의 재연결·고아 작업 정리와 전원 손실 복구는 별도 미완료 항목이다.

IPC 수명과 플랫폼 차이는 [Node.js 공식 문서](https://nodejs.org/api/net.html#ipc-support)를 따른다.
