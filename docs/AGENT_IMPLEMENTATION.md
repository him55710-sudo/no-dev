# 설계에서 구현으로: 개발판 사용·검증

시스템 설계 패널의 `설계만 저장`은 문서만 저장한다. `저장하고 구현`은 명시한 목표·정책·입출력·예외·유지 조건·완료 기준과 정적 호출 범위를 구현 작업에 전달한다. 자동 분석·파일 감지·문서 저장은 에이전트를 시작하지 않는다.

## 사용 조건

- 신뢰한 로컬 Git 저장소의 최상위 폴더. 첫 커밋이 있어야 한다.
- 저장되지 않은 편집기 변경은 먼저 저장한다. 기존 staged/unstaged 변경은 원본 상태를 유지한 채 스냅샷에 포함한다.
- 로그인된 Codex CLI. 설정 `pureobom.codexPath`로 실행 파일을 지정할 수 있다. 모델 설정을 비우면 설치된 CLI의 설정을 사용한다. 토큰은 풀어봄이 읽거나 Webview에 전달하지 않는다.
- `package.json`의 `test`, `typecheck`, `check`, `build` 중 실행할 명령을 선택한다. 임의의 모델 응답을 검증 명령으로 실행하지 않는다.
- 사용자가 외부 코드 전달을 선택한 뒤 시작한다. 작업에 필요한 명령이나 권한에 대한 Codex 요청은 작업 패널에서 허용·거절한다. 지원하지 않는 서버 요청은 명시적으로 거절한다.

## 실행 흐름

실행기 연결 확인·실제 검사 명령 표시·프로젝트별 선택 보관과 해제는 [구현 설정](EXECUTION_SETTINGS.md)에서 설명한다. 같은 컴퓨터의 프로젝트별 설정이며, 설정이 바뀌거나 다른 창에서 해제된 경우 기존 화면의 요청을 거절한다.

1. 현재 소스를 사용자 index와 분리된 임시 index로 스냅샷한다. Git 변환 필터와 줄바꿈 변환 없이 바이트를 보존한다.
2. VS Code 전역 저장 공간에 별도 Git worktree를 만든다. 원본의 파일을 자동으로 변경하지 않는다.
3. Codex App Server와 stdio 프로토콜로 연결한다. `initialize` → `thread/start` → `turn/start`를 사용하며, 완료 이벤트의 실제 상태를 검사한다.
4. 모델이 끝나면 제품이 선택된 검사 명령을 독립 실행한다. 실패 시 실제 결과를 넣어 한 차례 수정을 요청한다. 검사 누락·실패·시간 초과는 통과로 표시하지 않는다. 선택 후 바뀐 검사 명령도 거절한다.
5. 스냅샷 대비 변경 파일과 diff를 보여 준다. 범위 밖 파일·검사 파일 후보와 완료 기준별 확인 기록을 저장한 사용자가 반영한다. 미확인 기준은 명시적으로 선택해도 미확인으로 남고, 실패한 기준이나 검사 명령은 반영을 막는다. 구현 중 원본 파일·설계가 바뀌면 반영을 거절한다. [검토 기록의 사용법과 제한](IMPLEMENTATION_REVIEW.md)을 확인한다.
6. 반영 전에 복구 기록을 쓴다. 다중 파일 반영의 일부가 실패하면 적용한 파일을 되돌린다. 후속 사용자 편집과 충돌하면 덮어쓰지 않는다.

## 코드 기준 재확정과 다시 연결

작성 중인 설계는 확정·구현과 분리된 로컬 초안으로 자동 보관한다. 재시작 복원과 최신 설계 비교, 보관 완료 표시의 의미와 한계는 [DESIGN_DRAFTS.md](DESIGN_DRAFTS.md)를 확인한다.

구현 반영이나 외부 코드 변경 후, 저장된 설계의 `기준 코드 비교·다시 연결`을 연다. 기존 기준과 현재 관측 내용을 비교하고 연결할 파일·선언·규칙을 선택한다. `현재 코드 열기`로 근거를 읽고 검토 확인을 선택한 뒤 새 기준을 확정한다. 저장되지 않은 설계 편집은 먼저 저장해야 한다.

이 동작은 설계 ID와 원하는 동작·정책·완료 기준을 보존하면서 코드 연결과 기준선만 갱신한다. 이전 기준·대상·설계 리비전·교체 시각은 기록으로 남는다. 파일이나 선언이 사라져도 왼쪽 `저장된 설계`에서 기존 설계를 열 수 있다. 이름이 바뀌었거나 후보가 여러 개이면 사용자가 새 대상을 직접 선택한다. 이후 문서를 수정해도 같은 설계 ID와 기준 기록이 유지된다.

비교한 설계 리비전과 분석 해시가 달라졌거나 미저장 편집이 있으면 확정을 거절한다. 호스트는 새 분석과 실제 디스크 해시를 확인하고 설계 파일의 외부 변경도 검사한다. 외부 편집기를 잠그는 원자적 파일 시스템 스냅샷은 아니며, 이후 변경은 다시 드리프트로 표시된다. 새 기준 확정은 동작의 목표 충족을 선언하지 않는다. **코드 반영·기준 확정은 각각 별도 사용자 동작이며 기준 확정은 에이전트를 시작하지 않는다.**

기준 기록은 설계마다 최대 100개, 설계 파일 전체는 1MB까지 보관한다. 한도를 넘으면 저장을 거절하며 과거 기록을 자동 삭제하지 않는다. 기존 schemaVersion 1 문서는 기록 필드 없이도 읽는다. 이전 버전의 확장은 새 기록 필드를 지원하지 않으므로 해당 프로젝트를 열 때 최신 확장을 사용한다.

단위 테스트는 새 파일로 인한 범위 변경, 코드·설계 변경 중 비교 무효화, 명시적 재연결, 목표와 기록 보존, 이후 구현 범위를 검사한다. [실제 VS Code 검사](evidence/system-workspace/2026-10-16/baseline-integration.json)는 선언 이름 변경·미저장 편집 차단·재연결 후 문서 저장을 확인한다. [설치본 검사](evidence/system-workspace/2026-10-16/baseline-installed.json)는 반영 후 기준 확정, 재시작, undo 후 다시 기준 확정 및 다음 구현, 강제 종료 후 복구를 확인한다. [브라우저 화면](evidence/system-workspace/2026-10-16/baseline-review.jpg)은 합성 자료로 실제 React UI의 선택·확정·기록 표시를 조작한 결과이며 VS Code Webview 전체 조작 증거는 아니다.

## 이전 작업 열기와 파일 복구

화면 아래의 `이전 구현 작업`을 열고 기록을 선택한다. 저장 당시 상태와 현재 파일 상태는 구별한다. 완료된 검토는 변경 내용·선택한 검사 결과·확정했던 설계를 다시 불러온다. 작업 복사본이나 원본·설계가 바뀌었으면 예전 검사 결과로 반영하지 않는다. 이미 반영한 작업은 확장을 다시 열어도 이번 변경을 되돌릴 수 있다.

반영이나 되돌리기가 중간에 끊긴 경우 각 파일을 `변경 전`, `변경 후`, `다른 편집과 충돌`로 표시한다. `반영 전 파일로 복구`는 실제 파일 해시가 기록의 변경 전·후 중 하나와 일치할 때만 작동한다. 진행 로그에 없는 파일도 검사하므로 파일 쓰기와 진행 기록 사이의 중단을 구별한다. 시작 전 검사에서 충돌이 하나라도 있으면 해당 복구 요청은 파일을 변경하지 않는다. 복구 도중 새 편집이 발견되면 그 파일을 보존하고 미완료 상태를 남긴다. 파일을 직접 확인한 뒤 기록을 다시 열어 상태를 확인할 수 있다. 미완료 반영이 남아 있으면 새 작업 복사본 생성과 다른 작업의 반영을 막는다.

진행 상태는 버전이 있는 JSON으로 저장하며 임시 파일을 동기화한 뒤 교체한다. 복구할 때 경로, 스키마, 변경 내용의 해시, 원본 Git 스냅샷, 저장소 연결을 검사한다. 반영·되돌리기·복구는 같은 프로젝트의 다른 제품 프로세스와 동시에 실행하지 않는다. 이 조정에는 Windows의 명명된 파이프와 Linux의 추상 도메인 소켓을 사용해 TCP 포트 충돌·예약에 의존하지 않는다. 두 방식 모두 소유 프로세스 종료 시 운영체제가 자원을 해제한다([Node.js IPC 문서](https://nodejs.org/api/net.html#ipc-support)). 다른 운영체제는 로컬 루프백 포트를 사용하며 macOS는 아직 검증하지 않았다. 잠금을 얻지 못하면 반영을 거절하고 운영체제 오류 코드를 표시한다. 외부 편집기까지 잠그는 기능은 아니므로 파일 해시도 다시 검사한다. 잠금 방식이 다른 구버전과 신버전을 같은 프로젝트에서 동시에 사용하지 않는다.

에이전트 실행 중 연결이 끊긴 기록은 `이전 실행 연결 확인 필요`로 연다. 이전 승인 ID와 검사 통과 상태를 무효화하고 자동으로 에이전트를 실행하지 않는다. **이 표시는 이전 프로세스가 종료됐다는 뜻이 아니다.** 진행 중이던 에이전트와의 재연결, 잔류 프로세스 확인·종료, 그 복사본에서 검사 후 구현을 재개하는 흐름은 아직 제공하지 않는다. 준비 중 실패한 작업도 남아 있는 오류 기록을 볼 수 있다.

`tests/agent-recovery.test.ts`는 별도 Git 저장소와 실제 자식 프로세스 종료로 부분 반영·되돌리기·충돌·검토 복원·실행 실패 기록을 검사한다. 테스트의 일부 완료 기록은 저장·복원 검증용으로 구성한 자료이며 실제 모델 실행 증거로 간주하지 않는다. [검증 범위와 결과](evidence/system-workspace/2026-10-16/recovery-validation.json)를 함께 확인한다.

포트에 의존하지 않는 잠금, 프로세스 강제 종료 후 해제, 검사 시간 초과·취소 시 실제 자손 프로세스 종료에 대한 후속 검증은 [PROCESS_LIFETIME.md](PROCESS_LIFETIME.md)에 있다.

`.env`, 일부 자격 증명 설정·키 파일은 작업 복사본에서 제외한다. Git worktree는 보안 샌드박스가 아니며 공통 Git 저장소를 사용한다. 실행 제한은 Codex의 workspace-write 정책과 승인 처리에 의존한다. 이를 프로젝트 밖 파일 접근을 전부 차단하는 보장으로 설명하지 않는다.

## 확인한 증거

- 정적 분석·설계·Git 반영·프로토콜·실제 검사 실행의 회귀 테스트: `pnpm test`.
- VS Code 1.96.4 호스트에서 원문 왕복·설계 저장·외부 전달 선택·저장되지 않은 편집 차단: `pnpm extension:design-test`.
- 실제 VSIX를 독립 프로필에 설치하고 VS Code를 다섯 차례 실행해 검토·반영·되돌리기·강제 종료 후 복구 확인: `pnpm extension:build`, `pnpm extension:package` 후 `pnpm extension:recovery-test`. Linux에서는 마지막 명령을 `xvfb-run -a`로 실행한다.
- 실제 CLI 연결과 로그인 유무만 확인: `pnpm agent:connection`. 추론은 실행하지 않는다.
- 실제 모델이 합성 React/API 예제를 변경하는 별도 검증: `PUREOBOM_RUN_CODEX=1`을 설정하고 `pnpm agent:live-test`. CLI 승인 응답을 전달하려면 대화형 터미널에서 실행한다. 일반 CI는 추론을 실행하지 않는다.

2026-10-16 실제 실행에서는 UI·API·공통 정책·서비스·새 회귀 테스트의 **5개 파일**이 변경됐다. 고정한 인수 테스트를 수정하지 않고 **28개 테스트·타입 검사·빌드**가 통과했고, 반영 후 되돌려 원본 Git 상태가 복원됐다. [실행 결과](evidence/system-workspace/2026-10-16/live-design.json)와 [실제 변경](evidence/system-workspace/2026-10-16/live-change-review.json)을 보존한다.

이 검증은 합성 예제의 실제 실행이다. 호스트 저장소에 설치된 의존성을 사용했으며, 외부 프로젝트의 깨끗한 의존성 설치나 운영 인증·DB·Next 서버 검증을 대신하지 않는다.

후속 [외부 Next.js SaaS Starter 검증](../validation/next-saas-starter/README.md)은 별도 clone·의존성 설치·임시 SQL DB에서 실제 Codex가 UI/서버/정책/검사를 포함한 6개 파일을 변경했다. 고정 검사 9개, 추가 회귀 25개, 타입 검사, 명시적 검토 기록과 반영·재분석·undo가 통과했다. 미확인 기준 3개는 그대로 보존했다. 실제 개발 서버의 HTTP 팀 조회도 별도 확인했지만 production build·결제·계정 전체 회귀·브라우저/설치 Webview 전체 조작의 증거는 아니다. 원본 앱에 별도의 검사 환경을 추가한 사실과 정확한 실행 범위는 재현 안내와 원자료에 명시한다.

별도의 [설치본 복구 검증](evidence/system-workspace/2026-10-16/installed-recovery.json)은 실제 설치한 번들 해시와 Production 실행 모드를 확인했다. Windows에서 서로 다른 VS Code 확장 호스트로 검토 복원·실제 diff 열기·설계 수동 변경 및 미저장 편집 차단·반영·후속 편집 보존·되돌리기를 수행했다. 파일 세 개 중 하나가 반영되고 진행 로그에는 아직 기록되지 않은 순간 테스트 확장 호스트를 강제 종료했다. 다음 실행에서 파일 상태를 읽어 원본 바이트와 Git HEAD·index·기존 staged/unstaged 변경을 복구했다.

이 설치 검사는 외부 모델 대신 명시한 테스트용 stdio 응답기를 사용한다. 저장된 성공 기록을 만들어 넣지 않고 제품의 구현 요청·승인·실제 검사 경로를 실행하지만, 모델의 구현 품질을 증명하지 않는다. 별도 테스트 확장이 Webview와 동일한 입력 검증·실행 처리기를 호출하며, 마우스·키보드로 화면을 조작한 검증과도 구별한다. 재현용 파일과 제한은 [fixture 설명](../tests/fixtures/installed-recovery/README.md)에 있다.

## 아직 완료되지 않은 항목

- 설치본의 마우스·키보드 탐색 전체 흐름과 실제 외부 모델을 함께 사용하는 검증. 설치본 재시작·동일 요청 처리기·실제 반영 도중 확장 호스트 강제 종료·복구는 확인했다.
- 실행 중이던 에이전트의 잔류 프로세스 확인과 재연결·중단·검사 재개, 준비 실패로 남은 작업 복사본 정리. 파일 트랜잭션 동시 반영은 조정하지만 에이전트 세션 전체를 잠그거나 재개하지 않는다.
- 전원 손실·파일 시스템 자체 장애까지 포함하는 복구 보장과 중단 시 남는 임시 파일 정리.
- 더 깊은 관측·목표 비교와 기준 기록의 내보내기·정리 UI. 명시적 코드 재연결·기준 재확정·이전 기록 보존은 제공한다.
- 관측과 목표의 더 깊은 비교. [업무 기능 묶음](BUSINESS_FEATURES.md)의 생성·편집·다대다 연결과 기능에서 구현으로 이어지는 흐름은 제공한다.
- 설치본에서 구현 버튼부터 끝까지의 UI 검증, 독립 외부 프로젝트, 의존성이 없는 환경의 설치, Linux 실제 모델 실행.
- 검사 코드의 의미 변화나 테스트 약화를 자동 판정하는 기능. 범위 밖 파일·검사 파일 후보·기준별 사용자 검토 기록은 제공하며, 실제 테스트 사례와 요구사항의 자동 대응을 주장하지 않는다.

프로토콜 근거는 [공식 Codex App Server 문서](https://learn.chatgpt.com/docs/app-server)다. 현재 검증 버전은 `0.162.0-alpha.17.2`이며 다른 버전과의 호환성을 보장하지 않는다. React Flow·Dagre·Zod 및 전이 의존성의 라이선스는 실제 번들 입력과 패키지 메타데이터에서 생성한다.
