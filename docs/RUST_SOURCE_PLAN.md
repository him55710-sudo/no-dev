# Rust 원문 기능 구현 계획 · 통합 전 기록

2026-10-20 통합 전에 작성한 계획이다. 이후 0.7 개발판의 전용 읽기·직접 수정·문법 검사, humantime의 기존 테스트·복구, Windows·Ubuntu CI를 확인했다. **현재 구현·검증 범위는 [Rust 기능 문서](RUST_SOURCE.md)를 따른다.** 아래 단독 시험과 사전 기준은 당시 기록으로 보존한다.

## 선택한 파서와 사전 확인

공식 [tree-sitter-rust v0.24.2](https://github.com/tree-sitter/tree-sitter-rust/releases/tag/v0.24.2)의 WASM grammar와 [web-tree-sitter](https://github.com/tree-sitter/tree-sitter/blob/master/lib/binding_web/README.md)를 우선 검토한다. 현재 단독 시험 조합은 web-tree-sitter **0.27.1**, grammar **0.24.2**다. grammar의 공식 배포 digest와 내려받은 파일이 일치했다: SHA-256 `24c89bd9252255e4aebbcbd7d2d308bd92c86dd95a130fdc80efa49577b8d738`, 1,118,099 bytes. 이 조합은 별도 Rust SDK 없이 현재 파일을 로컬에서 파싱할 수 있었다.

무시되는 로컬 시험 폴더에서 Unicode/emoji·CRLF 위치, BOM, raw string·match, 잘못된 문법, 매크로 내용, 타입이 잘못된 함수의 6개 입력을 확인했다. 파서 위치로 JS 문자열을 잘랐을 때 원문과 일치했다. 매크로 안의 토큰과 타입 오류는 이 파서가 의미 검증하지 않는다는 사실도 확인했다. 제품 통합·원문 편집·undo·실제 Rust 프로젝트 테스트는 아직 하지 않았다. 제품 의존성이나 지원 표는 변경하지 않았다.

## 구현할 범위

- 파서와 grammar를 고정 버전·라이선스·해시로 패키지에 포함한다. 분석 시 다운로드, Cargo 실행, 프로젝트 플러그인·build.rs·proc macro 실행이 없어야 한다. 무거운 파싱은 worker에서 실행하고 크기·깊이·출력·시간 한도를 명시한다.
- 함수·impl 메서드·본문이 있는 trait 메서드, 매개변수, 지역값, 명시적 return과 마지막 식, if/else, match의 각 패턴·guard·결과, 반복, 호출을 한국어/영어로 원문에 연결한다. 코드 순서·분기 구조와 실제 실행 순서를 혼동하지 않는다.
- `?`, async/await, closure, 매크로, 속성·조건부 컴파일에는 실제 구문 범위와 한계를 표시한다. 매크로 내용을 일반 Rust 본문으로 해석하거나 임의 사업적 의미·타입·실행 시점을 만들어 내지 않는다.
- 지원되는 정확한 숫자·문자열·bool 값만 변경 대상으로 제시한다. 숫자 suffix와 큰 정수의 원문을 보존하고, 문자열 escape/raw delimiter 처리를 검증한다. 매크로·속성 안의 값을 근거 없이 편집 가능하다고 표시하지 않는다.
- 변경은 원문 범위 검증→후보 파싱→native diff→명시적 적용→undo를 거친다. 잘못된 문법·다중 식·주석 끼워넣기·오래된 원문을 차단한다. 문법 파싱을 타입·borrow checker·의존성·실행 동작 검사로 표시하지 않는다.
- 로컬 AI Rust 제안에도 같은 문법 검사와 명확한 미검증 범위를 연결한다. 원래 프로젝트의 `cargo test` 등은 사용자가 등록한 기존 명령으로 별도 실행한다.

## 지원 표를 바꾸기 전에 필요한 증거

1. 정규/문자열/raw·byte 문자열·숫자 suffix·한글/emoji·BOM/CRLF·불완전한 구문·큰 입력·취소의 회귀 검사. 의도적으로 파서가 검증하지 않는 타입·매크로 사례도 포함한다.
2. 실제 VS Code 원문 이동·Rust diff·미저장 편집·undo·오래된 변경안·문법 오류 적용 거절. 개발 호스트와 설치 패키지를 구분한다.
3. 공식 upstream의 고정 실제 프로젝트에서 원래 검사 기준선과 명시적 수정·회귀·복구를 확인한다. 주입 오류 검사는 실제 버그 발견이나 AI 유지보수 성공으로 부르지 않는다. 사용자 프로젝트 과제는 별도로 평가한다.
4. Windows/Linux 패키지에서 같은 고정 WASM 파일을 실제로 읽고 실행하는지 확인한다. 브라우저 데모에 연결하지 않았다면 VS Code 지원과 분리한다.

이 범위는 원래 [제품 완성 계획](PRODUCT_COMPLETION.md)의 Rust 항목을 구현하기 위한 단계다. 다른 언어, 모델 설명 품질, 실제 최적화, 사용자 사용성의 남은 요구사항을 대체하지 않는다.
