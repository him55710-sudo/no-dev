# 프로젝트별 구현 설정

시스템 설계 화면에서 실행기 연결을 확인하고, 외부 모델 전달 동의와 검사 선택을 이 컴퓨터의 프로젝트별 설정으로 보관할 수 있다. 자동 초안 저장이나 구조 갱신은 구현을 시작하지 않는다.

## 사용

1. 신뢰한 로컬 Git 프로젝트에서 **풀어봄: 시스템 설계 워크스페이스 열기**를 실행하고 구조를 선택한다.
2. **실행기·모델 설정**에서 설치한 Codex CLI의 경로와 선택할 모델을 지정한다. 모델을 비우면 CLI의 기본 설정을 따른다.
3. **Codex 연결 확인**으로 실행기와 로그인 상태를 확인한다. 이 작업은 `initialize`와 `account/read`만 요청하고 연결을 닫는다. 구현 요청, 설계 저장, 검사 명령 실행은 하지 않는다. 표시한 결과는 그 시점의 확인이며 실제 구현에서도 로그인 상태를 다시 검사한다.
4. 코드 전달 동의를 선택하고 실행할 검사를 고른다. 각 항목 아래에는 `package.json`의 실제 명령이 표시된다.
5. **이 프로젝트에 보관**하면 다음 실행에서 선택을 복원한다. 보관하지 않고 **저장하고 구현**으로 이번 작업만 실행할 수도 있다.
6. **보관 해제**는 이후 실행에 적용된다. 이미 시작한 구현은 작업 패널에서 취소한다.

보관된 설정과 현재 실행기 경로·모델 설정 값·패키지 매니저 종류·노출된 검사 명령이 다르면 동의가 해제되고 재확인 문구가 나타난다. 구조나 진행 상태가 갱신됐다는 이유만으로 입력 중인 선택을 초기화하지 않는다. 손상된 설정 파일은 덮어쓰지 않으며 읽기 오류를 표시한다.

## 저장과 실행 검증

VS Code 확장 전역 저장 공간의 `execution-profiles/<project-key>.json`에 저장한다. 프로젝트 키는 정규화한 실제 폴더 경로의 해시다. 같은 이름의 다른 폴더에는 적용되지 않는다. 프로젝트 소스나 `.pureobom/specs.json`, VS Code 동기화 설정에 실행 동의를 넣지 않는다. 계정 이메일·토큰·로그인 응답은 저장하지 않는다.

각 실행 요청은 화면에서 본 설정과 보관 기록의 리비전을 전달한다. 호스트는 현재 설정을 읽어 비교하고, 보관 설정을 사용하는 요청은 선택한 검사까지 일치하는지 확인한다. 다른 창에서 설정을 바꾸거나 해제하면 이전 화면의 요청은 거절한다. 보관 선택을 일부 바꾸어 이번 작업에만 사용하는 요청도 같은 리비전 검사를 거친다. 프로젝트별 실행 잠금과 원자적 기록 교체로 실행 시작과 다른 창의 설정 변경을 조정한다.

작업 복사본을 만든 뒤에도 선택한 검사 명령과 매니저를 확인한다. 구현 후 독립 검사는 기존 명령 또는 매니저가 바뀌면 실행하지 않고 실패로 기록한다. 실행 설정의 변경은 검사 결과나 완료 기준을 자동으로 통과시키지 않는다.

## 범위

보관 기능은 반복 입력을 줄이는 프로젝트 설정이다. 명령의 실제 파일·네트워크 효과를 제한하는 OS 샌드박스가 아니다. Codex가 요청하는 추가 명령·파일 승인은 기존 작업 패널에서 처리하며, 결과 반영에는 기존 범위·검사·완료 기준 검토가 필요하다.

비교 대상은 설정된 실행기 경로 문자열, VS Code 모델 설정 값, 매니저 이름, 검사 스크립트 문자열이다. 같은 경로의 실행 파일 교체, `PATH` 변경, CLI 기본 모델·설정 변경, 매니저 버전, 검사 파일 내용 전체까지 고정하는 기능은 아니다. 모델을 비워 두면 CLI 기본 모델이 달라질 수 있다. 계정·비용·호환성 확인을 대신하는 보장으로 표시하지 않는다.

## 검증과 재현

- `pnpm exec vitest run tests/execution-profiles.test.ts tests/agent-verification.test.ts tests/agent-recovery.test.ts`: 로컬 복원, 프로젝트 분리, 해제 후 오래된 요청 거절, 변경된 설정 거절, 잠금, 손상 기록 보존, 실제 검사 실행·실패·취소·복구.
- `pnpm extension:build && pnpm extension:design-test`: 실제 VS Code 호스트에서 검사 스크립트 변경과 보관 해제 후의 구현 차단. 설계가 먼저 저장되지 않는지도 확인한다.
- `pnpm extension:package && pnpm extension:recovery-test`: 설치 VSIX의 Production 모드, stdio 연결 확인과 중복 연결 거절, 다섯 번의 독립 실행에서 설정 복원, 구현·검토·반영·undo·중단 복구. 명시적인 테스트 응답기를 사용하며 실제 모델 품질이나 마우스 조작을 증명하지 않는다.
- `node scripts/preview-execution-settings.mjs` 후 `pnpm dev`: `/test-results/execution-preview.html`에서 실제 React 컴포넌트를 조작한다. 이 화면의 저장·연결 콜백은 브라우저 전용 테스트 응답이고 실제 CLI를 실행하지 않는다.

화면에서 초기 실행 차단, 선택 후 진행 갱신에도 선택 유지, 보관과 페이지 재시작 복원, 보관 리비전을 포함한 구현 요청, 검사 명령 변경 후 재확인, 보관 해제, 비신뢰 상태 차단을 확인했다.
