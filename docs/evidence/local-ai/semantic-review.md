# 설명 의미 검토 · 진행 중

2026-10-16. [사전에 정한 10개 사례와 기준](../../../examples/local-ai/semantic/README.md)을 사용한다. 기존 실패 4개와 새 합성 파일 6개다. 각 구현·모델·언어 조합에서 사례별 한 번씩 요청하고 결과를 보존한다. 개발자가 사례를 보며 지시를 작성했으므로 숨겨진 평가 집합이나 전체 언어 정확도 추정치가 아니다.

## 기준선과 첫 수정안

[기준선 3B 한국어](semantic-baseline-3b-ko.json)는 기존 `fe685a8` 프로토콜이다. [첫 수정안 3B 한국어](semantic-first-3b-ko.json)는 설명과 편집 지시를 분리하고 언어별 의미 지침을 추가했다. [해당 소스 변경](semantic-first-prompt.patch)은 기준선에 적용하는 diff다. 실행 시작 때 번들을 고정했으므로 이후 작업 트리 수정이 진행 중인 요청을 바꾸지 않았다. 모델 digest·프로토콜 해시·원문·전체 응답은 JSON에 있다.

| 사례 | 기준선에서 관찰 | 첫 수정안에서 관찰 |
| --- | --- | --- |
| Python 배송 | 상수만 인용, 분기·음수 예외 누락, 원문에 없는 원 단위 | 파일 주석 소개와 상수로 축소됨. 개선 실패 |
| Go 오류 반환 | 요약에서 음수 입력을 0 반환으로만 설명; 오류는 뒤 인용에 있음 | 인용의 오류/값 설명은 있지만 요약에서 오류 누락 유지 |
| CSS 열 | 600px 이하 한 열을 '가로로 한 줄'로 설명 | 기본 3열·600px 이하 한 열을 설명. 작은 화면을 모바일로 일반화하는 표현은 남음 |
| JSONC 배송 | 소비 코드 없이 무료 배송 비교 조건 단정 | 비교 조건과 '모든 배송에 비용 포함'을 단정. 개선 실패 |
| Python 묶음 계산 | `<= 0`을 `< 0`으로 설명하고 올림 나눗셈 설명 부족 | 경계 오류 유지, 산술식 설명도 틀림 |
| Go 첫 원소 | 빈 슬라이스·첫 원소와 존재 여부를 올바르게 설명 | 핵심 결과 유지. 슬라이스를 배열로 부르는 표현은 부정확 |
| CSS 다른 화면 조건 | 2fr/1fr·12px·900px 이상 세 열 설명 | 요약의 '첫 번째 열이 세 열로 변경'은 부정확; 인용에는 전체 열 수 변경이라고 설명 |
| JSONC 재시도 | 설정값은 읽지만 실제 소비 구현 부재를 구별하지 않음 | 별도 검토는 전체 원자료를 따른다 |
| TS 비동기 | 요약에서 빈 ID 경로 누락, '공백이나 탭이 있으면' 표현 모호, 실패 전파 누락 | 빈 ID 분기는 추가했으나 거절 전파·빈 문자열 유지 설명 누락 |
| SQL NULL | 전체 쿼리를 인용하지만 CASE 분기 설명 누락 | CASE 분기는 설명했으나 반환 열을 id·score로 읽을 수 있는 부정확한 표현 |

두 실행 모두 JSON 형식·원문 위치 검증은 통과했다. **형식 통과가 의미 정확성은 아니다.** 중요한 분기가 인용 안에 들어 있어도 그 설명에서 경계나 결과를 틀릴 수 있다. 단순 인용 포함률을 품질 점수로 사용하지 않는다.

## 두 번째 수정안: 같은 10개 한국어 사례

두 번째 수정안은 JSON 스키마에 실제 동작 설명을 요구하는 항목 설명을 붙이고, 사용자 요청에서 원문 뒤에 설명 요구를 두었다. [기준선에 대한 변경](semantic-second-prompt.patch), [3B 전체 응답](semantic-second-3b-ko.json), [7B 전체 응답](semantic-second-7b-ko.json). 3B는 Python 배송 1개를 먼저 요청하고 나머지 9개를 실행했다. 두 구간의 프로토콜·전송·고정 번들 해시가 같고 사례가 중복되지 않는지 확인해 합쳤으며 구간 시각과 ID를 보존했다.

| 사례 | 두 번째 수정안 3B | 같은 수정안 7B |
| --- | --- | --- |
| Python 배송 | 예외·무료 분기·기본 반환까지 설명/인용. 원문에 없는 원 단위 추측은 남음 | 세 경로를 설명/인용하지만 원 단위를 추측 |
| Go 오류 반환 | 요약에서 오류 누락, 함수 이름을 실제 `Fee` 대신 `ShippingFee`로 바꿈. 인용에는 세 반환 경로 | 오류를 요약에 포함. 기본 경로 설명을 '0보다 크고'로 표현해 0 경계를 누락, 두 반환값 설명 부족 |
| CSS 열 | 기본 3열·600px 이하 한 열 설명. `1fr`을 화면 폭 1/1로 설명한 오류 | 원문 인용 불일치/중복으로 거절. 의미 성공으로 세지 않음 |
| JSONC 배송 | 소비 코드 없는 비교·적용 방식 추측 유지 | 설정 파일이 금액을 입력받아 결정한다고 단정하고 `>` 비교를 추측 |
| Python 묶음 계산 | `<= 0`을 `< 0`으로 설명, 올림 계산을 몫으로 단순화 | `<= 0` 경계를 지킴. 식을 반복할 뿐 올림의 뜻·기본 size 4·타입 힌트 한계 설명은 누락 |
| Go 첫 원소 | 핵심 두 결과를 설명 | 핵심 두 결과를 설명. 비어 있는 첫 문자열 예시는 생략 |
| CSS 다른 화면 조건 | 두 열 2:1·900px 이상 세 열·12px 간격 설명 | 원문 인용 불일치/중복으로 거절 |
| JSONC 재시도 | 실제 3회 재시도·250ms 대기 동작으로 추측 | 최대 재시도·매번 지연·기본 비활성으로 단정. 소비 구현 부재를 구별하지 않음 |
| TS 비동기 | 빈 ID·fetcher·기본값을 언급하지만 빈 문자열 유지·거절 전파 미설명 | '비어 있음/없음'만으로 설명해 공백·nullish 경계가 불명확. 빈 문자열 유지·거절 전파 미설명 |
| SQL NULL | CASE 세 경로·active 조건을 설명하지만 반환 열 표현 부정확 | CASE 세 경로와 active 조건은 설명. 조회 결과 열과 저장된 열을 변경하는 동작의 구별은 명시하지 않음 |

3B는 10개, 7B는 8개가 형식·원문 검사를 통과했다. 이는 품질 점수가 아니다. 7B의 두 거절에서는 파서 오류만 보존됐고 거절 전 모델 원문은 남지 않았으므로 인용이 왜 틀렸는지까지 소급 추정하지 않는다. 후속 평가 도구에는 공개 예제에 한해 최종 답변 원문과 실제 요청을 보존하는 루프백 중계기를 추가했다. 모델의 사고 과정은 저장하지 않고 제품에는 로그 기능을 추가하지 않았다.

큰 모델만 선택하면 해결된다고 권할 근거가 없다. 입력 분기 안내의 일부 개선과 별개로, 경계·단위·소비 코드 추측이 남는다. 다른 로컬 모델과 영어 응답의 후속 자료를 아래에 구분해 추가한다.

## 다른 로컬 모델: Qwen3.5 4B 한국어

[공식 Ollama 배포](https://ollama.com/library/qwen3.5:4b)의 GGUF Q4_K_M, 다운로드 크기 3,324,173,934바이트, digest `d8b0f5e9760cd1682034f292d7ef72ec46f432149be0df7574bf2d6e92e38c04`를 사용했다. [모델 카드](https://huggingface.co/Qwen/Qwen3.5-4B)의 라이선스는 Apache 2.0이며 가중치를 이 저장소에 포함하지 않는다. Ollama 0.40.5의 `/api/show`가 `thinking.values:[false,true]`를 반환하여, 제품은 제한된 출력 예산을 최종 답변에 사용하도록 `think:false`를 요청한다. 이런 메타데이터가 없거나 false를 지원하지 않으면 임의 설정을 보내지 않는다.

[실제 한국어 10개 응답과 요청](semantic-qwen35-ko.json). 모두 형식·원문 검사는 통과했지만 의미 성공률로 부르지 않는다. 이전 모델과 시스템/사용자 프롬프트는 같고, 전송에서 지원되는 사고 끄기 설정이 추가됐다. 시간은 통제된 비교가 아니다.

| 사례 | 실제 의미 검토 |
| --- | --- |
| Python 배송 | 세 경로·ValueError·숫자는 맞지만 '소액 주문'으로 범위를 추측하고 subtotal을 부정확하게 번역 |
| Go 오류 반환 | 인용에는 값과 오류를 함께 설명. 요약의 '성공 없이 빈 결과'는 `0,nil`의 성공 결과와 모순 |
| CSS 열 | 3열·16px·600px 이하 한 열은 설명. '세로/가로 배치 비율'이라는 첫 표현은 불명확 |
| JSONC 배송 | 자체 실행하지 않는다고 말하면서도 비교 `>=`와 실제 배송비 부과를 단정. 개선 실패 |
| Python 묶음 계산 | 0 포함 경계와 올림 계산을 설명. 기본 크기 4·타입 힌트 한계는 생략 |
| Go 첫 원소 | 빈 슬라이스와 첫 원소의 두 반환값을 설명. 빈 첫 문자열 예시는 생략 |
| CSS 다른 화면 조건 | 열 수·900px 이상·간격을 설명. 첫 열의 실제 너비가 항상 두 배라는 표현은 과도함 |
| JSONC 재시도 | `enabled:false`만으로 실행되지 않음·다른 값이 적용되지 않음을 단정. 소비 구현 부재를 지키지 못함 |
| TS 비동기 | 요약의 trim 뒤 빈 값·nullish 기본값은 설명. 인용의 '공백이 있거나'는 비어 있지 않은 ID에도 해당하는 것처럼 오해시킴. 거절 전파 생략 |
| SQL NULL | 세 CASE 경로와 active 조건 설명. 정렬·속도·데이터 변경을 지어내지 않음 |

따라서 이 모델로 안내 예시를 교체하거나 모든 언어용 권장 모델이라고 선언하지 않았다. 같은 사례의 영어 요청은 별도 실행·검토한다. JSON/JSONC의 소비 동작 추측은 세 모델에 공통으로 나타나며, 프롬프트만으로 해결했다고 세지 않는다.

이 자료는 실행 시간 비교 실험이 아니다. 일부 요청은 다른 로컬 요청 또는 빌드·검사와 겹쳤으며, 소요 시간에 대기·모델 적재·PC 부하가 포함된다. 모델 출력은 실행·적용하지 않았다.
