# 언어별 실제 모델 응답 검토 (진행 중)

모델: `qwen2.5-coder:3b`, Ollama 0.40.5, Windows. [합성 사례와 기대 동작](../../../examples/local-ai/README.md)을 기준으로 실제 응답의 의미를 사람이 읽는 방식으로 검토했다. 여기서 '핵심 동작 일치'는 한 예제의 검토 결과이며 언어 전체의 정확도나 사용자 이해도 측정이 아니다.

| 언어 | 설명 검토에서 확인한 내용 | 아직 해결하지 못한 부분 |
| --- | --- | --- |
| JavaScript | 배송 기준·금액과 음수 오류를 인용으로 설명 | 음수 처리를 위해 50000 비교를 추가하라는 확인 항목은 잘못됨 |
| TypeScript | 배송 기준·금액·음수 오류 설명 일치 | 위험 목록에 근거 없이 '50000 이상 배송비 계산 오류'를 제시 |
| JSX | 수량이 정확히 0일 때 버튼 비활성화 설명 일치 | 단순 버튼 1개 사례에 한정; 이벤트 처리·부수 효과 미검증 |
| TSX | 타입이 있는 동일 버튼 사례의 동작 설명 일치 | 복잡한 props·상태·이벤트 미검증 |
| Python | 배송비 계산과 기준 숫자를 언급 | 조건을 '무료 배송 기준이 50000 이상'으로 부정확하게 표현하고 함수의 분기·음수 오류를 설명하지 않음. 주석·상수만 인용 |
| Go | 분기별 코드와 오류 반환 인용 | 요약에서 음수 입력을 '0 반환'으로만 설명해 함께 반환되는 오류 누락 |
| Rust | 음수 Err·무료 배송 Ok(0)·기본 Ok(3000) 설명 일치 | 무료 배송 설정의 이유를 '효율적일 수 있어서'로 추측. 코드로 알 수 없는 사업 의도 |
| Java | 입력 금액·예외·배송 기준·반환 금액 설명 일치 | 단일 정적 메서드 한정; 프로젝트·프레임워크 컴파일 검증 미포함 |
| C# | 예외 종류·배송 기준·반환 값 설명 일치 | 호출부 예외 처리 여부는 알 수 없음; 프로젝트 컴파일 검증 미포함 |
| HTML | POST 경로·필수 수량·최솟값·제출 버튼을 설명 | 서버의 주문 처리 구현은 없으므로 '주문을 처리하는 페이지'보다 '주문 정보를 보내는 폼'이 정확함 |
| CSS | 600px 이하 1열 규칙은 설명 | 기본 3열을 설명하는 인용에서 '세로로 배치'라고 잘못 설명 |

수정 작업은 요청한 특정 값·문구 외의 원문을 유지하는지 문자열로 확인한다. Python의 `70000`과 기대값 `70_000`은 같은 수지만 문자열 검사는 불일치로 남았다. 이는 동작 오류로 세지 않는다. 실제 언어별 실행·프로젝트 테스트는 이 응답 평가에 포함하지 않았다.

이번 첫 비교 실행은 **고정 32768 문맥**의 전송 코드를 시작 시 번들로 읽었다. 실행 중 개발 소스에 도입한 자동 문맥 선택과 분리한다. 일부 실행 동안 개발 빌드·테스트와 모델 다운로드가 동시에 진행됐으므로 소요 시간을 정밀한 모델 속도 비교로 사용하지 않는다. 전체 완료 후 원자료와 나머지 검토를 추가한다.
