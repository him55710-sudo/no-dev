# VS Code 확장 기능 구현·검증

검증일: 2026-10-16 (Asia/Seoul). 확장 버전 0.2.0. Windows, VS Code **1.96.4**의 별도 테스트 프로필에서 확인했습니다.

## 결과물

- 설치 파일: `release/pureobom-0.2.0.vsix`
- 안내: `extension/README.md`
- 소스: `extension/src`, `extension/ui`
- 원래 브라우저 시제품과 동일한 `src/core` 분석 엔진을 재사용합니다.
- 공개 Marketplace 게시나 사용자의 기존 편집기 프로필에 설치하는 작업은 하지 않았습니다. 패키지 설치 검증은 `test-results/packaged-extensions`에 격리했습니다.

## 구조

```text
VS Code 문서 (저장 전 수정 포함)
   → 300ms 입력 묶음 처리
   → 별도 Node Worker의 구문 분석·파일별 캐시
   → 한국어/영어 설명 · 규칙 표 · 상대 경로 지도
   → 원본 문서 ID와 버전에 연결된 변경안
   → VS Code 읽기 전용 비교 문서
   → TextEditor.edit / 기본 실행 취소 / 기본 저장
```

웹뷰는 입력값과 호스트가 발급한 문서·변경안 식별자만 보냅니다. 적용할 코드 전체를 웹뷰 메시지에서 받아 쓰지 않습니다. 호스트에서 원본 문서 URI, 버전, 전체 내용과 분석 문맥을 재확인하고, 편집기를 연 뒤에도 다시 확인합니다. 변경안 생성 이후 문서 변경·파일 전환 시 적용을 거부합니다.

UI 번들 약 220KB와 분석 Worker 약 3.4MB를 분리했습니다(비압축). 분석 Worker에 20초 제한을 두고, 오류·초과 시 종료 후 다음 요청에서 다시 만듭니다. 파일당 512KB, 합계 8MB, 최대 300개를 읽습니다. 명시적으로 전체 프로젝트 연결을 요청하기 전에는 열어 본 지원 파일만 분석합니다. VSIX는 약 1.1MB입니다.

## 자동 검증

- `pnpm extension:build`: TypeScript 검사와 네 가지 번들 생성 통과.
- `pnpm test`: 기존 엔진·경계 조건·성능과 웹뷰 입력 경계 **69개 테스트 통과**.
- `pnpm extension:test`: 공식 `@vscode/test-electron`으로 실제 확장 호스트에서 다음 **8개 통합 시나리오 통과**.

| 시나리오 | 확인한 내용 |
| --- | --- |
| 활성화 | 확장 활성화, 실제 웹뷰 패널 생성, 함수·편집 규칙 분석 |
| 저장 전 편집 | 50000 → 60000을 저장하지 않아도 설명이 갱신됨 |
| 비교 | 원본 60000 / 변경본 70000의 읽기 전용 VS Code 비교 문서 생성. 원본은 아직 변경되지 않음 |
| 적용·취소 | 70000을 편집기에 적용. 디스크는 50000 유지. VS Code 기본 Undo로 60000 복원 |
| 오래된 변경안 | 미리보기 이후 주석을 삽입하면 이전 변경안 적용 거부 |
| 지도·계산 | 상대 경로 helper.ts 연결, 모르는 경로 이동 거부, 배송비 계산 결과 3000 확인 |
| 문장 요청·파일 전환 | 한국어 요청으로 변경안 생성 후 다른 파일을 열면 적용 거부 |
| 원본 위치 | 설명의 줄 번호에서 실제 편집기의 해당 줄 선택 |

원자료는 `docs/extension-integration.json`입니다. 테스트는 격리된 예제 폴더와 프로필에서 실행됩니다. 명령은 필요한 VS Code 아카이브를 `.vscode-test`에 다운로드하며 정상 설치본을 변경하지 않습니다.

## 검증의 범위

실제 VSIX를 별도 프로필에 설치해 한국어 설명 패널과 규칙 편집 화면을 확인했습니다. 화면에서 무료 배송 기준 카드를 선택하고 70000을 입력해 변경안을 만든 다음, 적용 버튼을 눌러 실제 문서와 표가 70000으로 갱신되고 저장 전 상태로 남는 것도 확인했습니다. 좁은 패널의 표는 가로 스크롤을 사용하고 변경안은 생성 후 화면에 들어오도록 보완했습니다. 최종 패키지의 번들이 빌드 결과와 바이트 단위로 일치하는지는 `extension-package.json`에 기록했습니다.

API 검증은 위 8개 시나리오에 한정합니다. 제한 모드의 수정 차단은 코드에 구현했으나 별도 비신뢰 창으로 통합 검증하지 않았습니다. 원격 개발, macOS/Linux, vscode.dev, 대형 실제 프로젝트와 사용자 이해도 평가는 검증 대상에 포함되지 않습니다.

VS Code 확장 구조는 공식 [Webview 안내](https://code.visualstudio.com/api/extension-guides/webview), [확장 테스트 안내](https://code.visualstudio.com/api/working-with-extensions/testing-extension), [VSIX 패키징 안내](https://code.visualstudio.com/api/working-with-extensions/publishing-extension)를 참고했습니다. 연구 근거와 제품의 미검증 가설은 [연구 노트](RESEARCH.md)에 구분해 두었습니다.
