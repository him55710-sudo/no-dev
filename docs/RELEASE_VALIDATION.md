# 0.5.0 검증

2026-10-16, Windows / Node.js 24.19.0 / pnpm 11.25.0.

- 핵심 자동 검사 **107개 통과**. JSX 구조, 조건 분기, 이벤트 호출 시점, 컴포넌트·spread 경계, 표시 한도, 엔티티·공백·CRLF 보존, 마크업 형태 입력의 문자열 처리, 반복 편집과 오래된 변경안 거부를 검증했다.
- 웹·확장 타입 검사와 프로덕션 빌드 통과. 웹 UI JS 271.6KB / gzip 88.2KB, 별도 분석 Worker 3.64MB. 새 의존성을 추가하지 않았다.
- 실제 VS Code 1.96.4 통합 검사 **12개 통과**. 새 React 예제 명령, TSX 구조, 원문 위치, 문구 변경안, 편집기 적용·재분석과 기본 실행 취소를 검증했다. [원자료](extension-integration-0.5.json).
- 로컬 브라우저에서 버튼 문구를 `무료로 시작하기` → `14일 무료 체험`으로 바꾸는 변경안·적용·변경 기록·되돌리기를 확인했다.

- 0.5 VSIX를 별도 프로필에 설치하고 실제 화면 구조를 확인했다. 제한 모드에서 설명을 읽을 수 있고 적용이 제한됨을 확인했다. [설치본 화면](interface-vscode.png).
- 브라우저 한·영 설명과 React 변경안에서 계산 비교 버튼이 숨겨짐을 확인했다. 높이가 작은 화면에서 편집 패널 안을 스크롤해 적용 버튼을 클릭할 수 있도록 수정했다. 390×844 설정에서 가로 넘침 없이 clientWidth/scrollWidth 모두 375px였으며 오류 로그가 없었다.
- 공개 예제 전체를 `pnpm exec tsc -p examples/tsconfig.json`으로 타입 검사했다. 배포 ZIP·VSIX의 체크섬과 필수 파일 검사도 통과했다.

공개 배포 결과는 완료 후 추가한다. 실제 사용자 수요·이해도·재사용은 아직 측정하지 않았다.

# 이전 0.4.0 검증

2026-10-16, Windows / Node.js 24.19.0 / pnpm 11.25.0.

- 핵심 자동 검사 **93개 통과**. 사용자 용어의 선언 연결, 다른 함수·블록의 동명 변수 구분, 파일 격리, 선언 이름 변경, 문장 수정, 언어별 초기화, 입력 한도와 캐시를 추가 검증했다.
- 웹 및 확장 타입 검사·프로덕션 빌드 통과. UI JS 265.6KB / gzip 86.4KB, 별도 Worker 3.63MB. 파서는 UI 번들에 포함하지 않는다.
- 별도 VS Code 1.96.4 통합 검사 **11개 통과**. 기존 9개 흐름에 용어 변경·문장 수정·오래된 변경안 무효화와 파일 전환·용어 초기화를 추가했다. [원자료](extension-integration-0.4.json).
- 생성한 **0.4.0 VSIX 실제 설치** 성공. 일반 VS Code 검증 프로필에서 사용자 용어를 지정한 뒤 **Developer: Reload Window**로 확장 호스트를 다시 시작했다. 설명과 규칙에 `재시작해도 남는 배송선`이 복구되는 것을 실제 화면에서 확인했다.
- 자동 테스트 호스트는 메모리 저장소를 사용하므로 프로세스 재시작만으로 저장 복구를 검사할 수 없었다. 위 재시작 확인은 일반 검증 프로필의 별도 수동 확인이며 자동 검사 수에 포함하지 않았다.
- 브라우저 일반 작업 공간에서 용어 저장 → 사용자 용어로 75,000 변경안 생성 → 새로고침 후 용어 복구 확인. 한국어·영어를 별도로 지정할 수 있음을 확인했다. 원본 식별자는 유지되었다.
- VSIX·소스·정적 체험 ZIP 생성 및 SHA-256/필수 파일/제외 경로 검사 통과. 새 버전의 외부 CI와 공개 주소 검증은 아래 공개 기록에 별도로 적는다.

성능 원자료는 [benchmark.json](benchmark.json). 합성 파일 엔진 측정이며 UI·네트워크·Worker 시작 비용을 포함하지 않는다. 사용자 이해도·실제 수요·재사용은 아직 측정하지 않았다.

## 자동 검사

- Vitest **82개 테스트 통과**. 기존 분석·수정·해석기·경계 조건·캐시 검증에 입력별 비교, 오래된 원본 거부, 입력 크기·개수 제한, Markdown 이스케이프, 특수 값 구별, 공개 예제 3개를 추가했다.
- TypeScript 검사 및 Vite **7.3.7** 프로덕션 빌드 통과.
- 확장 기능 타입 검사 및 esbuild 번들 통과. 패키징은 **@vscode/vsce 4.0.0**을 사용한다.
- 생성한 VSIX를 `test-results/oss-extensions`의 별도 설치 영역에 설치했고, VS Code CLI가 `pureobom-local.pureobom@0.3.0`을 반환했다. 사용자의 일반 확장 프로필은 수정하지 않았다.
- 소스 ZIP을 새 폴더에 풀어 `pnpm install --frozen-lockfile`부터 다시 시작했다. 이 독립 복사본에서도 82개 테스트·웹 빌드·확장 빌드·VSIX 생성이 모두 통과했다.
- `pnpm release:check`로 세 배포 파일의 SHA-256, 소스 필수 파일, 제외 경로, 정적 체험판의 상대 경로, 라이선스와 VSIX 버전·런타임 파일을 확인했다.
- 별도 VS Code **1.96.4**에서 통합 검증 **9개 통과**: 실제 웹뷰 생성, 저장 전 코드 반영, 네이티브 diff, 여러 입력의 실제 변경 전후 비교, 편집기 적용·실행 취소, 오래된 적용/비교 차단, 작업 공간 연결과 계산, 파일 전환 시 변경안 무효화, 원본 행 이동.
- Vite·Vitest·패키징 도구의 알려진 취약점 때문에 의존성을 갱신했다. 전체 `pnpm audit --json`에서 **알려진 취약점 0건**. 해당 시점의 레지스트리 보고 결과이며 외부 보안 감사가 아니다. 원자료: [dependency-audit.json](dependency-audit.json).

통합 테스트 환경의 VS Code 자체에서 mutex·proposal·Node deprecation 경고가 출력되었지만 테스트는 종료 코드 0과 9개 성공을 반환했다. 경고가 없는 실행이라고 주장하지 않는다.

## 크기와 성능

- 브라우저 UI JS 약 **260.8KB**, gzip 약 **84.7KB**; 파서는 별도 Worker 약 **3.62MB**. ZIP 도구는 별도 지연 로딩 청크다.
- 확장 UI JS 약 **230.5KB**, Worker 약 **3.4MB**, VSIX 약 **1.08MB**.
- 300개 작은 합성 파일의 최신 엔진 측정은 [benchmark.json](benchmark.json)에 있다. 네트워크·Worker 시작·UI 렌더링을 포함하지 않는다.

## 공개 전 남은 확인

GitHub 원격 저장소 생성·업로드, GitHub Actions 실제 Windows/Linux 실행, Pages 공개 주소, Marketplace publisher와 게시, 사용자 관찰·재사용 검증은 아직 완료되지 않았다. 로컬 VSIX는 Marketplace 게시물이 아니다. GitHub 계정은 연결되어 있지만 브라우저의 새 저장소 생성 화면에는 로그인이 필요하며, 현재 연결 도구에는 저장소 생성 기능이 없다.

공개 후에만 실제 링크와 CI 배지를 추가하고, 결과를 확인한 항목만 완료로 바꾼다.
