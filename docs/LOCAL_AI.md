# 로컬 AI 설명·수정 · Local AI

**0.7 개발판 기능.** GitHub에 공개된 0.6.0 설치본에는 없다. 모델 없는 기존 문법 분석은 그대로 사용할 수 있다. 로컬 AI는 선택 기능이며 현재는 **데스크톱 VS Code의 로컬 작업 공간**에서만 제공한다. 공개 브라우저 데모·원격 VS Code 연결은 이 기능을 제공하지 않는다.

## 준비와 사용

1. [Ollama](https://docs.ollama.com/windows)를 설치하고 로컬 모델을 다운로드한다. 실제 검증 환경은 Ollama **0.40.5**, `qwen2.5-coder:3b`다. 모델마다 라이선스·크기·품질이 다르다. 모델 가중치를 풀어봄의 MIT 코드와 같은 라이선스로 간주하지 않는다.
2. 실행 중인 Ollama를 종료한 뒤, 클라우드 기능을 끄고 다시 실행한다. PowerShell: `$env:OLLAMA_NO_CLOUD="1"` 다음 줄에 `ollama serve`. macOS/Linux: `OLLAMA_NO_CLOUD=1 ollama serve`. 별도 터미널에서 `ollama pull qwen2.5-coder:3b`로 예시 모델을 받을 수 있다. [공식 로컬 전용 설정](https://docs.ollama.com/faq).
3. 개발 소스에서 `pnpm install --frozen-lockfile`, `pnpm extension:build`, `pnpm extension:package`를 실행하고 생성된 `release/pureobom-0.7.0.vsix`를 VS Code에 설치한다. 최신 공개 릴리스와 개발 빌드를 구분한다.
4. 파일을 열고 **풀어봄: 로컬 AI로 설명·수정 / Pureobom: Explain and edit with local AI** 명령을 실행한다. **Ollama 연결 확인**에서 설치된 모델을 선택한다.
5. 설명·수정·최적화 제안 중 작업을 선택하고 요청한다. 현재 파일과 입력한 요청만 사용하며 프로젝트 전체나 환경 파일을 자동 첨부하지 않는다. 모델 답변은 틀릴 수 있으므로 원문과 함께 검토한다.
6. 변경안의 **원문과 직접 비교한 결과**와 **VS Code에서 전체 차이 검토**를 확인하고 명시적으로 적용한다. JS/TS 비교는 코드 내용·구조·주석 변경과 중괄호 수의 차이를 모델의 설명과 별도로 보여 준다. 문법 오류를 확인한 제안은 적용을 막는다. 타입·동작·성능은 별도 검증해야 한다. 적용은 편집 버퍼에 반영되며 편집기의 실행 취소로 되돌린다. 편집기 자동 저장 설정은 그대로 적용된다.
7. 저장한 뒤 **실제 프로젝트 검사**에서 등록한 테스트·빌드 명령을 확인하고 실행한다. [검사 설정·범위](PROJECT_CHECKS.md). Ollama 없이도 실행할 수 있으며 검사 결과는 실제 종료 코드와 함께 표시한다.

모델 설치와 다운로드에는 인터넷·디스크 공간이, 로컬 추론에는 PC 메모리·연산·전력이 필요하다. **풀어봄의 유료 AI API 키·호출 요금은 없다.** 외부 유료 API로 자동 대체하지 않는다. 실제 작은 Python 예제에서는 설명 22.3초, 수정 17.6초가 걸렸다. 단일 PC·모델·예제의 기록이며 응답 시간 보장이 아니다.

## 연결·검증 경계

- 확장 호스트가 숫자 루프백 주소 `127.0.0.1`로 직접 HTTP 연결한다. 프록시 탐색·다른 호스트·HTTP 리디렉션을 사용하지 않는다. 포트는 사용자 수준의 `pureobom.ollamaPort` 설정으로 지정한다. 검증 실행은 별도 포트 11435, 기본 제품 설정은 11434다.
- `/api/status`에서 `cloud.disabled: true`를 확인하고, `/api/tags`와 `/api/show`로 설치된 GGUF 텍스트 모델과 원격 모델 여부를 검사한다. 상태 API가 없거나 로컬 전용 설정을 확인하지 못하면 코드 전송을 시작하지 않는다. 로컬 서버 자체는 사용자가 신뢰하고 관리하는 Ollama여야 한다.
- 코드 24KB, 요청 2000자, 합산 프롬프트 예산을 제한한다. 입력을 몰래 잘라 처리하지 않는다. 응답 2MB 상한과 180초 추론 제한, 취소 기능이 있다. 큰 파일·느린 모델은 요청을 줄이거나 다른 모델이 필요하다.
- 생성 중에는 경과 시간을 표시한다. 완료 예상 시간이나 진행률이 아니며 모델 응답이 수 분 걸리거나 시간 제한에 도달할 수 있다.
- 인용한 문자열의 실제 존재와 유일한 위치를 확인한다. 변경 전 문자열도 원본과 대조하고 겹치는 변경을 거절한다. **각 변경은 최소 하나의 원문 인용과 겹쳐야 한다.** 이는 위치 검증이며 설명의 의미가 참이라는 증명은 아니다.
- 한국어를 요청했는데 설명 문구에 한글이 전혀 없는 응답은 거절한다. 원문 코드에는 이 검사를 적용하지 않는다. 한글 포함 여부는 최소 확인이며 번역·설명 품질 점수가 아니다.
- 파일 변경·전환은 요청과 제안을 무효화한다. 생성·차이 보기만으로 파일을 바꾸지 않는다. 모델은 셸 명령·도구 호출·파일 경로를 실행할 수 없다.
- JS/TS/JSX/TSX는 파서, JSON은 JSON 파서, JSONC는 주석·끝 쉼표를 허용하는 전용 파서로 제안의 문법을 확인한다. HTML/CSS는 원문 파싱, SQL은 명시적으로 선택한 SQLite 방언만 검사한다. Python은 설치된 인터프리터에서 고정된 `ast.parse` 프로그램을 `-I -S`로 실행하며 사용자 코드는 실행하지 않는다. [Go](GO_SOURCE.md)·[Java](JAVA_SOURCE.md)·[C#](CSHARP_SOURCE.md)는 설치 SDK의 고정 helper로 제안 문법을 확인한다. 도구가 없으면 미검증으로 표시하며 타입·실행 동작은 별도 확인한다. 정확한 제한은 각 언어 문서를 따른다.
- 원문 비교는 양쪽 모두 문법을 파싱할 수 있는 JS/TS/JSX/TSX에만 제공한다. 위치를 제외한 구문 구조·토큰 원문·주석 내용을 비교하며 문자열·템플릿·JSX 텍스트 안의 공백도 코드 내용으로 취급한다. 코드 토큰이 같을 때는 주석의 상대 위치도 확인한다. 줄바꿈 때문에 `return`의 의미가 달라지는 경우나 주석 이동도 단순 서식 변경으로 표시하지 않는다. 다른 언어에는 이 비교 결과를 표시하지 않는다. 이는 **요청 준수나 실행 결과 동등성의 증명은 아니다**. 코드·구조 변경 자체는 정상적인 수정일 수도 있으므로 자동 적용 차단 사유로 삼지 않는다.
- 모델 문맥 크기는 요청 바이트와 출력·채팅 형식의 여유분을 바탕으로 8192·16384·32768 중 선택한다. 작은 파일마다 최대 문맥을 예약하지 않으며 코드를 잘라 줄이지 않는다. 실제 메모리 사용·속도는 모델과 PC에 따라 달라진다.
- 제한된 4096 출력 토큰을 최종 답변에 사용하도록, `/api/show`의 `thinking.values`에 `false`가 있을 때만 `think:false`를 요청한다. 끄기를 지원하지 않는 모델이나 명명된 사고 수준을 임의로 바꾸지 않는다. [공식 설정 정의](https://docs.ollama.com/capabilities/thinking). 모델의 사고 과정은 표시·저장하지 않는다.

정확한 언어별 범위는 [지원 표](LANGUAGE_SUPPORT.md)에 있다. 모델의 '확인 항목'은 실행한 테스트가 아니다. 특히 최적화 제안은 실제 결과 동일성과 성능을 측정하기 전까지 채택 근거가 부족하다.

## 실제 결과와 알려진 실패

사용자가 지정한 실제 비공개 프로젝트의 가독성 요청에서는 무변경 응답 거절, 진단 재시도의 180초 시간 초과, 안내 보강 후 요청 밖 중괄호 추가가 발생했다. 마지막 제안은 문법과 인용 검증을 통과했지만 검토에서 거절하여 적용하지 않았다. 원래 실패들을 보존하며 성공한 편집으로 집계하지 않는다. 안내 문구 개선만으로 모델 품질이 해결됐다고 주장하지 않는다. 비공개 소스·응답·상세 보고서는 로컬에만 보존한다. [실제 프로젝트 평가 절차](REAL_PROJECT_EVALUATION.md).

원자료와 재현 방법은 [검증 사례](evidence/local-ai/README.md)를 따른다. Python 외부 프로젝트에서 모델 → 원문 선택 → native diff → 실제 적용 → 변경 전후 테스트 297개 → undo와 원본 저장 복구를 수행했다. 이는 한 사례의 연동 성공이며 모든 언어·모델의 품질 보장이 아니다.

첫 모델 제안은 변경과 관계없는 import를 근거로 들었다. 위치는 실제였지만 설명과 변경을 뒷받침하지 않아 변경-인용 겹침 검사를 추가했다. 보강 후 제안도 불필요한 타입 확인을 추가했다. 기존 테스트와 추가 동일성 사례를 통과했지만 측정한 문자열 처리에서 **24~38% 느렸으므로 채택하지 않았다**. 테스트 통과만으로 좋은 최적화라고 판단하지 않는다.

실제 한국어 UI 요청에 영어 설명이 온 사례도 있었다. 한국어 기본 요청과 최소 언어 검사를 추가한 뒤 한국어 응답을 받았지만, 파일 주석만 요약한 빈약한 답변이어서 설명 품질 검증을 통과한 것으로 세지 않는다. 작은 모델 한 개의 연결 성공과 유용한 설명의 정확성을 구분한다.

이후 입력·조건·결과를 요구하도록 기본 요청을 보강하고 14개 언어 식별자의 28회 실제 응답을 [검토](evidence/local-ai/language-review.md)했다. 작은 3B 모델의 설명 오류와 SQL 수정 거절이 남았다. 별도 7B 모델의 CSS 설명 한 건은 정확했지만 이 PC에서 109.7초가 걸렸다. 더 큰 모델이 항상 정확하거나 빠르다는 보장은 없다. 원하는 모델을 직접 설치해 선택할 수 있으며, 설치 모델은 API 비용 없이 로컬에서 추론한다.

[분기·경계·데이터 의미의 후속 검토](evidence/local-ai/semantic-review.md)는 같은 10개 사례에서 기준선과 두 차례 안내 수정, 실제 3B·7B 및 추가 모델의 결과를 비교한다. 설명과 편집 요청을 구분하고 언어별 오류·반환값·CSS 열·JSON 데이터의 한계를 지시했지만 의미 오류가 남는다. 원문 인용을 통과했다고 이해가 정확하다는 표시는 하지 않으며, 특정 모델을 모든 언어의 권장 모델로 인증하지 않았다.
