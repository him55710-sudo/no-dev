# 더 쉬운 독립 앱 경험 — 전환 검토안

2026-10-20. 사용자는 현재 화면이 훨씬 더 쉬워야 한다고 지적했고, AI 오케스트레이션 앱 Orca처럼 독립 앱을 제공하여 GitHub 링크·저장소·폴더를 넣으면 코드를 이해하기 쉽게 설명하는 방향을 제안했다.

**더 쉬운 경험은 새 요구다.** 아래 독립 앱의 세부 흐름과 구현 순서는 그 요구에 대한 제안이며, 이미 구현하거나 사용자 검증을 마친 것으로 표시하지 않는다. 기존 기획 원문은 역사적 기준으로 보존한다.

## 제안하는 기본 경험

1. **프로젝트 넣기.** 첫 화면의 큰 영역에 폴더를 끌어 놓거나 GitHub 주소를 붙인다. 폴더 선택 버튼과 최근 프로젝트도 제공한다. 폴더는 현재 위치에서 읽고, 원격 저장소는 앱이 관리하는 작업 사본으로 가져온다.
2. **내 앱 이해하기.** 먼저 “무엇을 하는 앱인지”, 주요 기능 카드, 대표적인 사용 흐름을 짧은 한국어로 보여준다. 파일 트리·노드 그래프·설계 입력 폼은 첫 화면에 동시에 펼치지 않는다.
3. **궁금한 기능 열기.** 예를 들어 “회원가입”을 누르면 사용자가 입력한 내용이 어떻게 검사되고 저장되는지 순서대로 읽는다. “왜 이렇게 설명했나요?”에서 실제 코드 근거를 연다. 확인한 사실·추정·읽지 못한 부분을 구분한다.
4. **원하는 동작 말하기.** 선택한 기능에서 “이렇게 바꾸고 싶어요”를 작성한다. 긴 설계 문서는 이 입력에서 발전시키고 필요한 조건만 단계적으로 확인한다.
5. **변경 이해하고 적용하기.** 바뀌는 동작·영향받는 기능·검사 결과를 먼저 설명한다. 변경 코드와 상세 검사 기록은 펼쳐 볼 수 있고 반영·되돌리기를 제공한다.

설명만 제공하는 도구로 전체 목표를 축소하지 않는다. 기존의 구조·목표·코드 근거·다중 파일 구현·검토·복구 연결은 유지하고, 사용자가 한 번에 이해해야 하는 화면과 용어를 줄인다.

## Orca에서 참고할 점

[Orca 공식 안내](https://www.onorca.dev/)는 여러 코딩 에이전트, 작업 공간, 터미널, diff, 브라우저를 하나의 앱에서 다룬다. 독립 앱과 작업 관리 방식을 참고할 수 있다. 풀어봄의 기본 화면은 프로젝트 이해와 원하는 변화에 집중하고, 에이전트 선택·병렬 작업·상세 실행 관리는 필요한 경우에만 연다.

GitHub 저장소를 설명과 구조도로 바꾸는 기능은 이미 [GitDiagram](https://github.com/ahmedkhaleel2004/gitdiagram)에도 있다. 단순히 독립 창을 제공하거나 저장소 요약을 생성하는 것만으로 차별성을 주장하지 않는다. 비개발자가 기능의 동작을 이해하고 그 기능을 수정·검토하는 데 도움이 되는지는 아직 검증해야 할 제품 가설이다.

## 현재 구현에서 재사용할 것

- `src/workspace/analyze.ts`와 구조·관계·설계 모델은 공급받은 코드에서 분석하므로 독립 앱에서도 재사용할 후보이다.
- 기존 React 기반 읽기·구조 화면과 초안·변경 검토의 일부를 공유할 수 있다. 기본 화면의 정보 순서와 표현은 다시 설계한다.
- `extension/src/designWorkspace.ts`의 폴더 수집, 메시지 전달, 소스 열기, 저장 위치, 작업 실행은 VS Code에 연결돼 있다. 이를 공통 서비스와 앱별 연결 코드로 분리해야 한다.
- 실제 수정·검사·취소·오래된 결과 차단·부분 반영 복구의 보장을 독립 앱에서도 검증한다. VS Code에서 통과했다는 사실로 독립 앱의 완성을 주장하지 않는다.

앱 껍데기만 바꿔 현재 복잡한 화면을 그대로 옮기는 것으로 완료 처리하지 않는다.

## 구현을 시작할 때 확인할 결과

- VS Code를 설치하거나 실행하지 않고 앱에서 로컬 폴더와 GitHub 저장소를 열 수 있다.
- 원본을 옮기거나 변경하지 않고 첫 설명을 읽을 수 있다.
- 주요 기능과 실제 근거를 연결한다. 폴더명만으로 업무 의미를 확정하지 않는다.
- 처음 화면에서 터미널·브랜치·심볼·스키마를 알아야만 진행하는 단계가 없다. 인증이나 모델 연결은 필요한 시점에 쉬운 안내로 제공한다.
- 읽지 못한 파일·분석 제한·모델 설명 실패를 숨기지 않는다. 큰 저장소를 일부만 읽었으면 전체 분석으로 표시하지 않는다.
- 설명에서 설계 수정, 실제 다중 파일 구현, 검토·반영·복구까지 이어진다.
- 실제 사람의 이해도·도움 요청·과제 완료 여부는 별도 측정한다. 현재 참가자 결과는 없다.
