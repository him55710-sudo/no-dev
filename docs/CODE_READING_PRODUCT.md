# 코드를 쉬운 설명으로 읽고 수정하기 — 현재 제품 기준

2026-10-20. 사용자는 “파일마다 쓰여진 코드를 완전 해석하기 쉽게, 뭘 위해 쓰였고 어떻게 해석되며 어떤 식으로 수정할 수 있는지” 보여주기를 원한다고 정정했다. 이 해석을 확인한 뒤 “그래 이제 완벽하게 만들어”라고 구현을 요청했다.

현재 기준은 **각 파일의 코드를 비개발자가 이해하고 수정할 수 있는 설명으로 푸는 것**이다. 앱 미리보기 중심의 앞선 제안은 사용자에게 거절됐으며 제품의 기본 화면으로 구현하지 않는다. 구조도는 보조 도구다.

## 완료에 필요한 경험

1. GitHub 저장소 또는 로컬 폴더를 가져와 읽는다. 독립 앱에서 사용할 수 있으며 VS Code 연동도 유지한다. 이름과 폴더 구조를 알아야만 코드를 찾을 수 있게 하지 않는다.
2. 파일마다 무엇을 위한 코드인지 쉬운 제목과 역할을 보여준다. 기능 이름만 바꾼 요약으로 끝내지 않는다.
3. 각 파일의 모든 코드를 의미 있는 부분으로 나누고, 받는 정보·조건·처리 순서·만드는 결과·예외를 쉽게 해석한다. 원문의 어느 부분에 해당하는지 확인할 수 있어야 한다.
4. 기본은 설명을 읽는 화면이며, 필요한 경우 원문을 설명과 나란히 볼 수 있다. 설명 범위에서 빠지거나 지원하지 않는 코드는 숨기지 않는다.
5. 왜 이렇게 작성했는지 설명하되, 원문에 적힌 이유·추정·알 수 없는 이유를 구분한다. 작성자의 의도나 다른 파일의 동작을 지어내지 않는다.
6. 현재 동작, 수정할 수 있는 항목, 쉬운 말로 쓴 수정 요청 예시, 바뀔 결과와 함께 확인할 영향을 보여준다.
7. 사용자가 설명에서 고른 부분과 요청이 실제 코드 수정에 이어진다. 요청은 직접 고칠 수 있다. 오래된 설명이나 다른 파일을 가리키는 요청은 차단한다.
8. 실제 변경 전후 설명·검사 결과를 검토하고 반영·되돌리기를 수행한다. 오류·취소·재연결·원본 보호도 유지한다.
9. 실제 모델 해석의 품질, 실제 앱 조작, 코드 수정·검사·반영·복구를 확인한다. 단위 검사나 고정 예시만으로 전체 완성을 선언하지 않는다.

## 현재 구현과 확인 범위

- `src/workspace/codeReading.ts`: 원문 줄 보존, 설명 단위와 읽는 순서의 누락·중복 검사, 작성 이유·수정 제안의 원문 인용 검사, 선택한 설명과 수정 대상의 버전 검사.
- `ProjectNarrator.readFile`: 원문을 생략하지 않고 나누어 읽고, 검증한 부분만 캐시한다. 큰 파일의 세부 설명을 다시 요약해서 없애지 않는다. 실패한 응답은 한 번 재시도하고, 취소된 결과를 새 설명으로 내보내지 않는다.
- `CodeReading` 및 `ProjectReader`: 쉬운 제목으로 찾기, 파일별 상세 해석, 설명·원문 나란히 보기, 수정 요청 준비, 기존 다중 파일 구현·검토·복구 연결. 읽기 화면을 기본 진입점으로 바꾼다.
- 독립 앱의 폴더/GitHub 가져오기와 공통 실행 서비스 연결은 아직 남아 있다.
- 전체 코드 줄에 설명을 연결했다는 사실은 의미 해석의 정확성이나 실제 실행 성공을 뜻하지 않는다. 실제 결과를 별도로 확인한다.

## 검증 기록

구체적인 검사와 실제 모델·화면·설치 검증 결과는 `AGENT_WORKLOG.md`와 관련 evidence에 기록한다. 이 문서의 요구 목록을 현재 통과한 검사에 맞춰 축소하지 않는다.

2026-10-20 [실제 모델·화면·설치 검증](evidence/code-reading/README.md)에서 배송비와 142줄 파일의 상세 해석, 문맥 보강 전후, 실제 네 파일 수정·검사·전후 설명·반영·독립 동작 9개·undo를 확인했다. 검토를 막은 pnpm 캐시 문제와 수정 기록도 포함한다. 독립 앱과 모든 프로젝트에 대한 완성을 뜻하지 않는다.
