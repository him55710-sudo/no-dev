# 함수 생성 코드와 처리 본문 읽기

구조 화면의 **저장한 구현 기준**에서 화살표 함수, 함수 표현식, 함수 생성기의 전달 본문을 읽을 수 있다. 이전에는 선언의 시작 위치와 함수의 시작 위치가 다른 경우 설명을 놓쳤다. 예를 들어 `const removeTeamMember = validatedActionWithUser(schema, async (...) => { ... })`는 `data 선언`으로만 보였다.

TypeScript Compiler API의 선언·타입과 기존 코드 읽기의 함수·단계 분석을 연결했다. 괄호와 타입 단언으로 감싼 함수도 본문과 대응한다. 이름, 노드 ID, 원문 범위와 컴파일러 연결은 그대로 유지한다.

## 서로 다른 실행 단계를 구분한다

- **직접 선언한 함수**: 매개변수, 조건의 본문과 else, 반환, try/catch/finally를 순서와 들여쓰기로 표시한다.
- **호출 결과로 받은 함수**: 생성 호출 결과를 보관한다는 설명과, 정적 타입에서 호출 가능한 값이라는 근거를 표시한다. 생성 호출과 나중의 함수 실행을 합치지 않는다.
- **인수로 넘기는 함수**: 어느 호출의 몇 번째 코드상 전달 항목인지 구분하고 그 함수 본문을 별도로 설명한다. 받는 쪽이 언제·몇 번 실행하는지는 단정하지 않는다. 펼침 인수 뒤에도 실제 런타임 인수 번호라고 주장하지 않는다.
- **반환하는 함수**: 바깥 함수가 반환하는 값이라는 설명 뒤에 반환 함수의 본문을 따로 보여 준다. 인증 래퍼를 선택하면 반환 함수에 들어 있는 로그인·입력 검사도 확인할 수 있다.

확인할 수 없는 외부 라이브러리 반환형은 미확인으로 남긴다. 다른 변수에 정의된 내부 함수를 바깥 함수의 실행 단계로 펼치지 않는다. 중첩된 호출의 직접 함수 인수는 읽지만, 조건식·객체·배열에 담긴 간접 함수 선택과 여러 겹의 반환 함수 전체를 복원하는 기능은 아니다. 해당 원문을 숨기거나 실행 완료로 표시하지 않는다.

설명에는 생성·전달·반환 구문에서 직접 확인한 사실만 넣는다. 서버 액션 안의 팀 소속 검사와 래퍼 안의 인증 검사를 하나의 증명된 실행 경로로 합치지 않는다. 사용자 의도, 라이브러리의 실행 계약, 실제 입력값, 권한 요구사항 충족은 별도 확인이 필요하다.

## 읽기와 저장 한도

한 선언의 요약은 최대 40줄, 본문 텍스트 5,500자 내에서 구성한다. 긴 한 줄은 앞 600자와 생략 기호를 보여 주며, 남은 처리 내용이 있으면 원문 확인 안내를 붙인다. 기존 단계 보고서를 순차적으로 읽어 한도에 도달하면 중단한다. 원문 범위와 내용 해시는 전체 선언을 계속 보존한다.

구조 패널은 들여쓰기를 보존한다. 설계의 관측 비교는 기존 보관 한도에 따라 요약을 더 생략할 수 있고, 생략 여부를 표시한다. 사용자 목표와 이전 설명은 그대로 남는다. 설명 개선만으로 코드 변경이나 목표 달성을 주장하지 않으며, 실제 콜백 본문이 바뀌면 코드 근거의 변경으로 감지한다. 줄 번호를 설명 문자열에 포함하지 않아 단순한 줄 이동으로 처리 설명을 다시 쓰지 않는다.

## 검증 방법

```powershell
pnpm exec vitest run tests/workspace-function-bodies.test.ts tests/workspace-observations.test.ts tests/workspace-callbacks.test.ts tests/system-workspace.test.ts --maxWorkers=2
node scripts/check-function-summaries.mjs '<준비한 Next baseline Git 폴더>' 377fea7
```

두 번째 명령은 지정한 이전 Git 커밋의 `src` 분석 코드와 현재 코드를 각각 묶어 같은 외부 앱 파일을 읽는다. 앱 코드·모델·프로젝트 검사 명령을 실행하지 않는다. `test-results/function-summaries.json`에 실제 이전/현재 설명, 역할, 원문 범위, 파일 해시와 보존 결과를 남긴다.

외부 Next 앱의 52개 분석 파일에서 `removeTeamMember`, `inviteTeamMember`, `customerPortalAction`이 데이터 선언 안내에서 함수 값과 전달 본문 설명으로 바뀌었다. `validatedActionWithUser`, `withTeam`에는 반환 함수의 인증·입력·팀 검사 설명이 추가됐다. [최종 보완 후 비교 기록](evidence/function-summaries.json)에서 다섯 선언의 ID·원문 범위 및 정적 연결 302개는 전후 동일하며 원본 추적 파일 57개와 Git 상태도 보존됐다.

## 2026-10-20 검증 기록과 미해결 실패

초기 전체 회귀는 **259개 중 251개 통과·8개 실패**했다. [전체 결과](evidence/function-regression-initial.json)를 보존한다. 관리 호스트 4개, 프로토콜 초기화 2개, 복구 2개 검사에서 프로세스·상태 대기 시간 초과 또는 제한 시간 내 종료되지 않는 실패가 발생했다. 원인을 확인하지 않은 채 환경 문제로 단정하거나 전체 통과로 표시하지 않는다. 이 실행에서 함수 본문 5개, 관측 7개, 함수 전달 3개, 구조 12개와 제어 흐름 9개 검사는 통과했다.

별도 [설계 호스트 검사 39개](evidence/function-design-host.json)는 통과했다. 이 기록은 마지막 `unknown` 타입 단언 분류 보완 전 실행이다. 설치 화면의 선언·요약·원문을 기록하는 계측도 추가했으나, 이번 함수 설명 변경의 새 설치 화면 검증은 아직 수행하지 않았다.

최종 보완에서는 함수 본문이 명시돼 있으면 `as unknown`으로 타입을 감춰도 함수로 분류하고, 별칭의 본문 안내가 원래 선언을 가리키도록 했다. 이 변경을 포함한 [관련 검사 36개](evidence/function-targeted-final.json)는 모두 통과했다. 이 제한된 재검증이 위 전체 회귀의 실패를 해결했다는 의미는 아니다.

최종 소스의 `pnpm build`, `pnpm extension:build`, `pnpm extension:package`도 통과했다. 새 VSIX를 생성했지만 이 패키지로 설치 화면을 다시 조작한 결과는 아직 없다.

직전 커밋 `377fea7`의 [CI 실행](https://github.com/him55710-sudo/no-dev/actions/runs/39328562690)은 Ubuntu 성공·Windows 실패다. Windows는 `agent-host.test.ts`의 중단 작업 이어하기 검사에서 첫 승인 상태 대기가 초과됐으며, 그 뒤 빌드와 설치 검사는 실행되지 않았다. 이번 로컬 실패와 이전 CI 실패를 각각 미해결 상태로 남긴다.
