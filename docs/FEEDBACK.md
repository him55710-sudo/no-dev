# From a demo to a real task

Open **Install & feedback / 설치·피드백** in the browser, or **Help & feedback / 도움말·피드백** in the VS Code panel. The guide links to the actual releases and repository and explains how to install the VSIX. A completed browser-demo edit also exposes a next-step card.

## Share an experience

1. Choose the example or your own project, then select completed, stuck or unsupported. The outcome has no default selection.
2. Describe what you tried. Optionally add what worked or got in the way.
3. Review the entire Markdown summary locally. It contains only your answers, the app version, browser/VS Code environment and explanation language. Source, file names, workspace identifiers and device details are not attached.
4. Copy the summary. Editing an answer invalidates the earlier preview, so review it again before copying.
5. If you want to share it, open the GitHub feedback form, paste the summary and submit it yourself. GitHub requires sign-in and submitted issues are public. The link contains only the template name, never the entered answers.

There is no analytics endpoint, automatic issue creation, background upload or persistent feedback store. The draft lives in the open dialog. Clipboard copying writes the reviewed summary only. Existing browser workspace storage is independent of the feedback dialog.

These are voluntary, self-reported accounts. They cannot establish an activation rate, retention rate, independent user count or task success rate by themselves. Synthetic verification entries are labeled as such and are never submitted as customer feedback.

## What maintainers should do

- Separate example use from own-project use. A successful example is not evidence that a real project worked.
- Preserve completed, stuck and unsupported outcomes. Do not convert missing results into success.
- Ask for a minimal public/synthetic reproduction when needed; avoid requesting a whole private repository.
- Record the next reproducible improvement and link its fix to the feedback issue.
- Keep [the five-person observation protocol](USER_STUDY.md) separate from unsolicited reports, downloads and GitHub stars.
