# 공통 후보 검토의 관찰자 안내

참가자에게 미리 제공하지 않는다. `pnpm study:package`는 참가자 ZIP과 별도의 근거 보고서를 만든다. ZIP에는 이 문서·정답 매핑을 넣지 않는다. 검사 출력의 실제 실패 정보는 숨기지 않는다. 순서를 번갈아 제시하고 실시간 작업 결과와 따로 기록한다.

| 후보 | 기록과 답변 판단                                                                                                                                                                                                                                                                                                                                          |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A    | 실제 모델 후보에서 서버의 두 `canManageTeamMembers(userWithTeam.teamRole)` 검사를 제거한 **제어된 실패**. AI가 만든 실패라고 부르지 않는다. UI는 B와 같은 바이트이고 타입 검사는 통과하지만, member의 직접 초대·제거 검사 2개가 실패한다. 반영 의사를 표하면 알려진 실패 승인으로 기록한다. 보류/거절 이유가 틀렸다면 결정과 이해 점수를 별도로 기록한다. |
| B    | 실제 Codex 작업 `29da2265-df2a-4efc-b630-bc4f458f7d8a`의 일곱 파일 후보. 당시 고정 검사 9개와 타입 검사는 통과했다. **모든 요구가 입증된 정답 후보라고 부르지 않는다.** 당시 검토의 `invariant:0`(인증·계정·결제 유지 및 외부 동작)과 `invariant:2`(설치 과정)는 미확인이다. 추가 근거를 요구하는 답은 타당하다.                                          |

핵심 관찰은 화면 차단과 서버 권한 검사, 타입 검사와 정책 충족, 현재 팀 역할과 계정 역할을 구별하고 미확인 범위를 인식하는지다. 별도 관찰자가 조건 정보 없이 설명 원문을 채점할 수 있다. 단순 승인 여부로 이해를 추론하지 않는다.

A의 서버 파일 SHA-256은 `401c23583fcbad63be192f0b53fe026be2256e670ab7af0df369305dc83232f9`, B는 `bcc6ea871829fb11fe14e4cab11d056c50c9af4f80798fcd4e91e00db4e9a18e`여야 한다. 생성기가 과거 기록의 해시와 일치하지 않으면 중단한다. 두 후보의 나머지 여섯 파일과 변경 전 파일은 동일해야 한다. 고정 검사 파일·잠금 파일 보존 근거도 과거 기록끼리 일치하는지 확인한다.

근거: [실제 모델 후보](../evidence/system-workspace/2026-10-20/installed-next-candidate.json), [검토·반영 기록](../evidence/system-workspace/2026-10-20/installed-next-verification.json), [고의 누락 실행](../evidence/system-workspace/2026-10-20/missing-server-guards.json). 두 후보는 동일 시각·동일 모델의 비교가 아니다. 생성기는 기록을 읽고 소스 바이트를 검증할 뿐 테스트·모델·설치 UI를 새로 실행하지 않는다. 당시 추가 회귀·브라우저 시험을 공통 자료에 섞어 모든 유지 조건이 통과했다고 주장하지 않는다.

공통 과제는 ZIP 파일을 읽는 보조 관찰이며 저장 작업 가져오기나 네이티브 검토 UI를 검증하지 않는다. 실제 제품 흐름의 효과는 별도 실시간 과제로 관찰한다. 참가자의 결정은 제품 반영 차단과 별도다. 제품이 A를 거절한 과거 동작을 참가자의 올바른 판단으로 세지 않는다.
