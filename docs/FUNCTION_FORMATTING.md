# 선택한 함수의 줄바꿈 정리

**0.7 개발 소스의 VS Code 기능**이다. 안정판 0.6.0과 웹 데모에는 아직 포함되지 않았다. JS/TS 함수의 촘촘한 본문·조건문·변수 선언을 줄바꿈과 2칸 들여쓰기로 정리한다. 모델·Ollama·API 키·네트워크 연결이 필요하지 않다.

1. JS/TS/JSX/TSX 파일을 열고 풀어봄의 **이해하기**에서 함수를 선택한다.
2. **이 기능의 줄바꿈 정리**를 누른다. 원문은 아직 바뀌지 않는다.
3. **바꾸기**에 나온 변경안을 읽고 **VS Code에서 코드 차이 보기**를 연다.
4. 변경 범위가 맞으면 편집기에 적용한다. 자동 저장하지 않으며 Ctrl+Z로 한 번에 되돌릴 수 있다.
5. 필요하면 저장 후 **확인하기 → 기존 프로젝트 명령**으로 원래 테스트를 실행한다. 테스트 명령 실행은 별도의 명시적 동작이다.

이미 같은 서식이면 변경안을 만들지 않고 안내한다. 미리보기를 열기 전에는 호스트에서도 적용을 거절한다. 원문·문서 버전·현재 문서가 달라지면 이전 변경안은 적용할 수 없다.

포매터는 포함된 TypeScript 5.9.3의 언어 서비스와 구문 위치를 사용한다. 프로젝트의 포매터 설정이나 플러그인을 읽거나 실행하지 않는다. 현재는 2칸 공백으로 고정되어 있으므로 팀의 다른 서식 규칙과 같다고 보장하지 않는다. 파일은 UTF-8 기준 128 KiB 이하, 구문 탐색 깊이는 200 이하여야 한다. 선언 함수·함수 표현식·화살표 함수·메서드 중 읽기 화면에 나온 기능을 대상으로 하며 선택한 함수 안에 포함된 중첩 코드도 범위에 들어간다.

변경 전후 파일 전체의 문법, 토큰 원문, 구문 구조, 주석 내용과 상대 위치를 대조한다. 문자열·템플릿·JSX 내용의 공백은 보존해야 한다. 선택 범위 밖의 바이트가 달라지거나 위 비교를 통과하지 못하면 제안 생성을 거절한다. 이 검사는 **일반적인 실행 결과 동등성의 증명은 아니다**. 코드 문자열을 관찰하는 `Function.prototype.toString()`이나 줄 번호에 의존하는 도구 등은 서식 변경에도 영향을 받을 수 있다.

이 기능은 설명 생성·버그 수정·성능 최적화가 아니다. 다른 언어의 서식 정리, 모든 문법과 프로젝트, 사용자 직접 조작의 편의성은 아직 검증하지 않았다. [실제 검증과 한계](evidence/local-ai/function-format.md), [기존 프로젝트 검사 연결](PROJECT_CHECKS.md)을 참고한다.
